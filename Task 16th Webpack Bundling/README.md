# Практическое занятие №16. Использование инструментов автоматической сборки (WebPack)

Работа про сборку проекта: два модуля ES6 собираются WebPack в один минифицированный
файл. Первый модуль считает процент одного значения от другого, второй выводит состояние
задачи и процент её выполнения. Страница подключает готовый бандл обычным тегом `script`.

## Описание решения

```
Solution/
    src/utils.js        функция процента и константа задачи
    src/index.js        точка входа: импорт, обработка формы, вывод
    index.html          страница с <script src="dist/main.js">
    webpack.config.js   конфигурация сборки
    package.json        зависимости и команда build
    dist/main.js        собранный и минифицированный бандл
```

В методичке десять вариантов. Взят шестой: модуль считает процент одного значения от
другого (часть / целое), второй модуль показывает текущее состояние задачи и процент её
выполнения. `src/utils.js` отдаёт функцию `percentOf` и константу `TASK`, `src/index.js`
применяет их к введённым числам и выводит результат.

Методичка предлагает положить в `src` три файла, включая html. Страница лежит в корне
`Solution`, потому что подключает `dist/main.js` относительным путём: из `src` этот путь
указывал бы на несуществующий `src/dist/main.js`. Для WebPack в `src` важны только
js-файлы, они и образуют граф зависимостей.

## Как запустить

Из папки `Solution`:

```bash
npm install
npm run build
```

Дальше открыть `index.html`. В отличие от пятнадцатой работы сервер не обязателен:
WebPack собрал модули в один обычный скрипт, директив `import` в браузере уже нет, поэтому
ограничение CORS не действует. Если удобнее проверить по HTTP, папку можно отдать
командой `python -m http.server 8940`.

## Модуль utils

`src/utils.js` содержит данные задачи и саму формулу:

```js
export const TASK = {
    title: "Курсовая работа",
    done: 26,
    total: 40,
};

export function percentOf(part, whole) {
    if (whole <= 0) {
        return 0;
    }

    const value = (part / whole) * 100;
    return Math.min(Math.max(value, 0), 100);
}
```

`TASK` хранит название задачи и начальные значения, чтобы страница не дублировала их в
разметке. `percentOf` делит часть на целое и умножает на сто. Проверка `whole <= 0`
защищает от деления на ноль и от отрицательного целого: в этом случае функция возвращает
ноль. `Math.min(Math.max(...))` ограничивает результат диапазоном от 0 до 100, иначе при
`part > whole` полоса выполнения вышла бы за свой максимум. Оба имени экспортируются
именованно, наружу отдаётся ровно то, что нужно второму модулю.

## Модуль index

`src/index.js` — точка входа. Он импортирует оба имени и работает с разметкой:

```js
import { TASK, percentOf } from "./utils.js";

const doneInput = document.getElementById("done");
const totalInput = document.getElementById("total");
const result = document.getElementById("result");
const bar = document.getElementById("bar");

function render() {
    const done = Number(doneInput.value);
    const total = Number(totalInput.value);
    const percent = percentOf(done, total);

    result.textContent =
        `Задача «${TASK.title}»: выполнено ${done} из ${TASK.total} — ${percent.toFixed(1)}%`;
    bar.value = percent;
}

doneInput.value = TASK.done;
totalInput.value = TASK.total;

document.getElementById("calculate").addEventListener("click", render);
render();
```

Ссылки на элементы берутся один раз при загрузке, а `render` вызывается и сразу, и по
кнопке. `Number()` превращает строку из поля ввода в число. В тексте процент округляется
до одного знака через `toFixed(1)`, а в `progress` записывается сырое значение, чтобы
полоса двигалась плавно. Начальные значения полей берутся из `TASK`, поэтому данные задачи
описаны в одном месте. Экспортировать из точки входа нечего: это начало графа, файл только
запускает приложение.

## Страница

`index.html` содержит заголовок, два числовых поля, кнопку, абзац результата и элемент
`progress`:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>Процент выполнения задачи</title>
</head>
<body>
    <h1>Процент выполнения задачи</h1>

    <label for="done">Выполнено</label>
    <input id="done" type="number" min="0" step="1">

    <label for="total">Всего</label>
    <input id="total" type="number" min="1" step="1">

    <button id="calculate" type="button">Рассчитать</button>

    <p id="result"></p>
    <progress id="bar" max="100" value="0"></progress>

    <script src="dist/main.js"></script>
</body>
</html>
```

Идентификаторы совпадают с теми, что ищет `index.js`. Подключён только собранный файл:
ни одного `import` и ни одной ссылки на `src` на странице нет, браузер вообще не знает, что
исходников было два.

## Сборка

`webpack.config.js` повторяет конфигурацию из методички:

```js
const path = require('path');

module.exports = {
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'main.js',
  },

  mode: 'production',
};
```

`entry` задаёт первый файл, с которого WebPack строит граф: дальше он читает `import` в
`index.js`, находит `utils.js` и включает его в сборку. `output.path` через
`path.resolve(__dirname, 'dist')` указывает папку `dist` рядом с конфигурацией, а
`filename` — имя готового файла. `mode: 'production'` включает минификацию Terser.

Запуск и вывод сборки:

```
> webpack-bundling@1.0.0 build
> webpack

asset main.js 532 bytes [emitted] [minimized] (name: main)
orphan modules 275 bytes [orphan] 1 module
./src/index.js + 1 modules 979 bytes [built] [code generated]
webpack 5.112.0 compiled successfully in 1853 ms
```

Строка `orphan modules` показывает `utils.js`: 275 байт, столько занимает исходный модуль.
Отдельным модулем в бандле он не остался, потому что WebPack применил scope hoisting и
встроил его содержимое прямо в обёртку точки входа.

Результат сборки, файл `dist/main.js`:

```js
(()=>{"use strict";const e=document.getElementById("done"),t=document.getElementById("total"),n=document.getElementById("result"),u=document.getElementById("bar");function c(){const c=Number(e.value),l=Number(t.value),d=function(e,t){if(t<=0)return 0;const n=e/t*100;return Math.min(Math.max(n,0),100)}(c,l);n.textContent=`Задача «Курсовая работа»: выполнено ${c} из ${l} — ${d.toFixed(1)}%`,u.value=d}e.value=26,t.value=40,document.getElementById("calculate").addEventListener("click",c),c()})();
```

В собранном виде от двух модулей осталась одна самовызывающаяся функция. Комментарии,
переносы строк и отступы удалены, имена переменных сокращены до одной буквы: `doneInput`
стал `e`, `totalInput` — `t`, `percent` — `d`. Функция `percentOf` осталась функцией,
потому что её аргументы появляются только во время работы страницы. Итоговый файл занимает
532 байта вместо 979 байт исходников, при этом поведение не изменилось.

## Проверка

Страница открывалась в браузере на локальном сервере, значения вводились в поля и
считались по кнопке. Ошибок в консоли нет, `dist/main.js` загружается одним запросом.

| Выполнено | Всего | Результат | Полоса |
| --- | --- | --- | --- |
| 26 | 40 | 65.0% | 65 |
| 7 | 9 | 77.8% | 77.78 |
| 50 | 40 | 100.0% | 100 |
| 40 | 0 | 0.0% | 0 |

Последние две строки проверяют ограничения из `percentOf`: процент не поднимается выше
ста, а деление на ноль даёт ноль вместо `Infinity` или `NaN`.

## Теоретическая часть

WebPack — статический сборщик модулей. Он начинает с точки входа, читает все `import`,
переходит по ним и собирает полный граф файлов, которые нужны приложению. Затем граф
превращается в один или несколько файлов, понятных браузеру.

У сборщика три основных преимущества. Объединение сокращает число HTTP-запросов: вместо
десятков модулей браузер получает один файл. Оптимизация уменьшает размер: в режиме
`production` работает Terser, который удаляет комментарии и пробелы и сокращает имена
локальных переменных. Совместимость позволяет смешивать в проекте ES Modules и CommonJS,
хотя в этой работе используются только ES Modules.

Конфигурация WebPack — обычный JavaScript-объект, который экспортируется через
`module.exports`. `entry` задаёт первый файл, `output` — папку и имя результата, `mode`
включает встроенную оптимизацию. В режиме `development` код остаётся читаемым, в
`production` минифицируется.

Директивы `import` и `export` обрабатываются на этапе сборки. В готовом бандле их нет:
WebPack сам расставляет модули в правильном порядке и сохраняет их области видимости.
Именно поэтому страница после сборки работает как с обычным скриптом, без
`type="module"` и без HTTP-сервера.

Минификация — это уменьшение размера кода без изменения поведения. Удаляются пробелы,
переносы, комментарии и лишние скобки, имена локальных переменных сокращаются до одного-двух
символов. Дополнительно WebPack применяет scope hoisting: небольшие модули встраиваются
друг в друга, и обёртки вокруг каждого модуля не создаются.

## Ответы на вопросы

Контрольных вопросов в методичке этого занятия нет, поэтому вопросы составлены по
теоретической части.

**1. Что такое WebPack и зачем он нужен?**

Это сборщик модулей. Он строит граф зависимостей от точки входа и собирает все файлы в
один бандл, попутно оптимизируя код. Браузеру не нужно загружать десятки отдельных
модулей.

**2. Что задаёт параметр entry?**

Первый файл, с которого начинается анализ. От него WebPack идёт по директивам `import` и
находит остальные модули. В этой работе точка входа — `src/index.js`.

**3. Зачем в output нужен path.resolve?**

Он превращает относительный путь `dist` в абсолютный относительно папки с конфигурацией.
Так бандл попадает в нужную папку независимо от того, из какого каталога запущена сборка.

**4. Что включает mode: 'production'?**

Встроенную оптимизацию: минификацию Terser, сокращение имён, удаление неиспользуемого
кода. В режиме `development` этих преобразований нет, и бандл остаётся читаемым.

**5. Как WebPack обрабатывает import и export?**

Он читает их на этапе сборки, находит нужные файлы и включает их в граф. В готовом файле
директив модулей уже нет: код модулей встроен в общую обёртку, а их области видимости
сохранены.

**6. Что такое минификация?**

Уменьшение размера кода без изменения его поведения. Удаляются пробелы, переносы строк и
комментарии, сокращаются имена локальных переменных и функций.

**7. Чем WebPack отличается от Babel?**

Babel переписывает синтаксис одного файла под старые браузеры, но не объединяет файлы.
WebPack собирает модули в один бандл и оптимизирует его. Обычно их используют вместе:
сначала Babel транспилирует код, потом WebPack собирает результат.

**8. Почему после сборки странице не нужен HTTP-сервер?**

Потому что в бандле не осталось `import` и `export`. Браузер получает обычный скрипт,
подключённый тегом `script`, а ограничение CORS относится только к загрузке модулей.
