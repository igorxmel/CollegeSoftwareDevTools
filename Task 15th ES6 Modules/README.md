# Практическое занятие №15. Использование модулей в проектах JavaScript

Работа про стандартную модульную систему JavaScript. Проверка сообщения на спам
разделена на два модуля: первый ищет запрещённые слова, второй формирует текст
результата. Страница подключает итоговую функцию через `<script type="module">` и
показывает ответ.

## Описание решения

```
Solution/
    spam-check.js       первый модуль, поиск запрещённых слов
    message-checker.js  второй модуль, текст результата
    index.html          страница с type="module"
```

В методичке десять вариантов. Взят шестой: функция `checkSpam(str)` возвращает `true`,
если строка содержит «кредит» или «XXX». Задание требует три файла, поэтому логика
разнесена ровно на два модуля и страницу.

## Как запустить

Модули не работают через `file://`, поэтому страницу нужно отдать по HTTP. Из папки
`Solution`:

```bash
python -m http.server 8940
```

Дальше открыть http://localhost:8940. При открытии файла двойным щелчком браузер выдаст
ошибку CORS, потому что модули загружаются по правилам этого протокола.

## Первый модуль

`spam-check.js` содержит саму проверку:

```js
const SPAM_WORDS = ["кредит", "xxx"];

export function checkSpam(text) {
    const normalized = text.toLowerCase();
    return SPAM_WORDS.some((word) => normalized.includes(word));
}
```

Список слов вынесен в константу, строка приводится к нижнему регистру, поэтому «кредит»
находится и в слове «КРЕДИТ». `some()` перебирает слова до первого совпадения и дальше не
идёт. Наружу экспортируется одна функция, сам массив остаётся внутренним делом модуля.

## Второй модуль

`message-checker.js` импортирует функцию из первого и добавляет вторую часть логики:

```js
import { checkSpam } from "./spam-check.js";

export function checkMessage(text) {
    if (checkSpam(text)) {
        return `Сообщение «${text}» содержит спам`;
    }

    return `Сообщение «${text}» не содержит спама`;
}
```

`checkMessage` превращает логическое значение в готовую фразу, которую странице остаётся
только вывести. Импорт именованный, поэтому имя в фигурных скобках должно совпадать с
тем, что экспортировано. Путь относительный и с расширением `.js`, без него браузер файл
не найдёт.

## Страница

`index.html` содержит поле ввода, кнопку и абзац для результата. Скрипт подключён с
атрибутом `type="module"`:

```html
<script type="module">
    import { checkMessage } from "./message-checker.js";

    const input = document.getElementById("message");
    const result = document.getElementById("result");

    document.getElementById("check").addEventListener("click", () => {
        result.textContent = checkMessage(input.value);
    });
</script>
```

Без `type="module"` браузер выполнил бы файл как обычный скрипт и не понял бы `import`.
Начальное значение поля заполнено спам-сообщением, чтобы результат был виден сразу после
нажатия кнопки.

## Проверка

Страница проверена на локальном сервере. В поле вводились сообщения с обоими
запрещёнными словами, с другим регистром и без них.

| Сообщение | Результат |
| --- | --- |
| Выиграйте кредит без процентов | содержит спам |
| Скидка XXX% только сегодня | содержит спам |
| КРЕДИТ под низкий процент | содержит спам |
| Встреча перенесена на завтра | не содержит спама |

Ошибок в консоли браузера нет, все три файла загружаются с сервера.

## Теоретическая часть

Модулем называют отдельный файл JavaScript со своей областью видимости. Переменные и
функции модуля не попадают в глобальную область и не видны другим файлам, пока их явно
не экспортируют. В модулях автоматически действует строгий режим.

Экспорт бывает именованным и по умолчанию. Именованный записывается как `export function
checkSpam() {}` и позволяет отдать несколько сущностей. Экспорт по умолчанию пишется как
`export default` и описывает одну главную сущность. Импорт повторяет форму экспорта:
именованный в фигурных скобках, по умолчанию без них.

Чтобы браузер включил модульную систему, скрипт подключается с `type="module"`. Такой
скрипт загружается отложенно и выполняется в своей области видимости. Модули работают по
правилам CORS, поэтому нужен HTTP-сервер, а не `file://`.

## Ответы на вопросы

Контрольных вопросов в методичке этого занятия нет, поэтому вопросы составлены по
теоретической части.

**1. Что такое модуль в JavaScript?**

Отдельный файл со своим кодом и своей областью видимости. Всё, что должно быть доступно
другим файлам, модуль экспортирует явно.

**2. Чем именованный экспорт отличается от экспорта по умолчанию?**

Именованный экспорт имеет имя и импортируется в фигурных скобках, таких экспортов в
файле может быть несколько. Экспорт по умолчанию один на модуль и импортируется без
скобок под любым именем.

**3. Зачем нужен атрибут type="module"?**

Он сообщает браузеру, что скрипт является модулем и в нём разрешены `import` и `export`.
Без атрибута браузер выполнит файл как обычный скрипт и на директивах модуля выдаст
ошибку.

**4. Почему модули не работают при открытии файла напрямую?**

Потому что браузер загружает модули по правилам CORS, а у страницы, открытой через
`file://`, нет источника, которому можно доверять. Нужен HTTP-сервер.

**5. Что даёт собственная область видимости модуля?**

Переменные модуля не засоряют глобальную область и не конфликтуют с переменными других
файлов. Наружу видно только то, что экспортировано.

**6. Как импортировать функцию из другого модуля?**

Указать путь к файлу и имя функции: `import { checkSpam } from "./spam-check.js"`. Путь
должен быть относительным и с расширением `.js`.

**7. Почему в модулях автоматически действует строгий режим?**

Это часть стандарта модулей. Строгий режим отключает неявные глобальные переменные и
другие небезопасные конструкции, поэтому модульный код проверяется жёстче обычного
скрипта.

**8. Что произойдёт, если импортировать несуществующий экспорт?**

Модуль не загрузится, браузер выдаст ошибку на этапе связывания модулей. Код внутри
модуля при этом не выполнится.
