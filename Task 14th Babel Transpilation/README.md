# Практическое занятие №14. Транспиляция кода с помощью Babel

Работа про Babel: установка, настройка `@babel/preset-env` и транспиляция современного
JavaScript под разные целевые браузеры. Три небольшие программы собираются дважды, под
современные браузеры и под IE 11, чтобы было видно, как параметр `targets` меняет
итоговый код.

## Описание решения

```
Solution/
    package.json              зависимости и команды сборки
    babel.config.json         конфигурация из методички
    babel.config.legacy.json  вторая конфигурация с целью IE 11
    script.js                 стрелочная функция, шаблонная строка, параметр по умолчанию
    arrays.js                 map(), filter() и стрелочные функции
    student.js                класс Student
    dist/                     сборка под современные браузеры
    dist-legacy/              сборка под IE 11
```

Сборки лежат в репозитории намеренно: именно они показывают результат транспиляции, и
проверить их можно без установки зависимостей. Исходники и конфигурации остаются
отдельными файлами, поэтому любую сборку можно повторить.

## Как запустить

Установить зависимости:

```bash
npm install
```

Собрать под современные браузеры:

```bash
npm run build
```

Собрать под IE 11:

```bash
npm run build:legacy
```

Запустить полученный код:

```bash
node dist/script.js
```

```bash
node dist-legacy/script.js
```

## Установка и настройка

Проект создан командами `npm init -y` и `npm install --save-dev @babel/core @babel/cli
@babel/preset-env`. Версия Babel 7.29.7. В `package.json` добавлены две команды, чтобы не
писать длинную строку с файлами каждый раз:

```json
"scripts": {
  "build": "babel script.js arrays.js student.js --out-dir dist",
  "build:legacy": "babel script.js arrays.js student.js --config-file ./babel.config.legacy.json --out-dir dist-legacy"
}
```

Основная конфигурация повторяет методичку:

```json
{
  "presets": [
    ["@babel/preset-env", {
      "targets": "> 0.5%, not dead"
    }]
  ]
}
```

Вторая конфигурация отличается только целями. Она нужна для пятого задания, чтобы
сравнить результат и не переписывать основной файл туда и обратно:

```json
{
  "presets": [
    ["@babel/preset-env", {
      "targets": {
        "ie": "11"
      }
    }]
  ]
}
```

## Транспиляция современного JavaScript

В `script.js` собраны три конструкции из задания: стрелочная функция, шаблонная строка и
параметр по умолчанию. Функция вызывается дважды, со значением и без него.

```js
const greet = (name = "Гость") => {
    return `Привет, ${name}!`;
};
```

Сборка под современные браузеры почти не изменила файл. Стрелочные функции и шаблонные
строки поддерживаются давно, поэтому `preset-env` не стал их переписывать. Видны только
две вещи: добавленная директива `"use strict"` и другие отступы. Строгий режим появился
потому, что Babel по умолчанию считает файл модулем.

В сборке под IE 11 та же функция выглядит иначе:

```js
var greet = function greet() {
  var name = arguments.length > 0 && arguments[0] !== undefined ? arguments[0] : "Гость";
  return "\u041F\u0440\u0438\u0432\u0435\u0442, ".concat(name, "!");
};
```

Стрелка стала обычной функцией, параметр по умолчанию превратился в проверку
`arguments`, шаблонная строка собрана через `concat`. Кириллица записана
escape-последовательностями, это тот же текст, просто в виде, безопасном для старых сред.

## Работа с массивами

`arrays.js` хранит массив чисел и применяет `map()` и `filter()` со стрелочными
функциями. Под современные браузеры Babel только убрал скобки вокруг единственного
параметра и переформатировал строки, сами методы остались вызовами. Под IE 11 стрелочные
функции стали обычными `function`, а `const` заменился на `var`.

Методы `map()` и `filter()` Babel не трогает, потому что это не синтаксис, а встроенные
методы массива. Если бы в целевой среде их не было, понадобился бы полифил, а не
транспиляция.

## Использование классов

`student.js` содержит класс `Student` с конструктором и методом `getInfo()`. Под
современные браузеры объявление класса осталось как есть. Под IE 11 Babel превратил его в
функцию-конструктор и добавил вспомогательные функции:

```js
function _classCallCheck(a, n) { if (!(a instanceof n)) throw new TypeError("Cannot call a class as a function"); }
function _createClass(e, r, t) { return r && _defineProperties(e.prototype, r), ... }
```

`_classCallCheck` запрещает вызывать конструктор без `new`, `_createClass` описывает
методы через `Object.defineProperty`. Это и есть цена совместимости со средой, которая
классов не знает.

## Сравнение целей

| Конструкция | `> 0.5%, not dead` | IE 11 |
| --- | --- | --- |
| стрелочная функция | осталась | стала `function` |
| параметр по умолчанию | остался | проверка `arguments` |
| шаблонная строка | осталась | `concat` |
| класс | остался | функция и helpers |
| `const` и `let` | остались | стали `var` |

Результат целиком определяется параметром `targets`. Один и тот же исходный файл при
современных целях остаётся почти нетронутым, а при цели IE 11 переписывается полностью.
Настройка не улучшает код сама по себе, она приводит его к тому уровню синтаксиса,
который указан в конфигурации.

## Теоретическая часть

Транспиляцией называют преобразование кода из одной версии языка в другую, обычно более
совместимую. Babel разбирает файл в синтаксическое дерево, применяет плагины и собирает
обратно в JavaScript. `@babel/core` выполняет преобразование, `@babel/cli` даёт команду
`babel`, а `@babel/preset-env` подбирает плагины под цели.

`targets` задаётся в формате browserslist. Чем старее цели, тем больше конструкций
переписывается. `babel.config.json` хранит эти настройки, и Babel находит его сам.

Транспиляция не заменяет полифилы. Babel меняет синтаксис, но не добавляет реализацию
`Promise`, `Array.from` и других встроенных методов. Для них подключают `core-js`.

От компиляции транспиляция отличается тем, что результат остаётся кодом на том же языке.
Компилятор переводит программу в машинный код или в другой язык, а транспилятор выдаёт
JavaScript для того же движка.

## Ответы на вопросы

**1. Что такое транспиляция?**

Преобразование исходного кода в другую версию того же языка, чаще всего в более старую и
совместимую. Программа делает то же самое, но записана другим синтаксисом.

**2. Для чего используется Babel?**

Для перевода современного JavaScript в код, который понимают старые браузеры и среды
выполнения. Ещё Babel применяют для JSX и других расширений синтаксиса.

**3. Чем транспиляция отличается от компиляции?**

При компиляции программа переводится в машинный код или в другой язык, а при
транспиляции результат остаётся кодом на том же языке и выполняется тем же движком.

**4. Какую роль выполняет @babel/preset-env?**

Это набор плагинов, который подбирается под указанные цели. По `targets` preset-env
решает, какие преобразования нужны, и подключает только их.

**5. Для чего предназначен файл babel.config.json?**

Он хранит настройки Babel для проекта: пресеты, их параметры и отдельные плагины. Babel
находит этот файл сам, поэтому команда сборки остаётся короткой.

**6. Как выполнить транспиляцию через командную строку?**

Командой `npx babel script.js --out-file dist.js`. Если добавить её в `scripts` файла
`package.json`, дальше достаточно `npm run build`.

**7. Как параметр targets влияет на результат?**

Он задаёт список сред, под которые нужно собрать код. Чем старее цели, тем больше
конструкций переписывается. Для современных браузеров код почти не меняется.

**8. Гарантирует ли Babel поддержку всех современных возможностей JavaScript?**

Нет. Babel меняет синтаксис, но не добавляет отсутствующие встроенные методы и объекты.
Для них нужны полифилы, а часть возможностей, например `Proxy`, полифилом заменить
нельзя.
