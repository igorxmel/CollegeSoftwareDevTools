# Практическое занятие №11. Разработка с использованием NodeJS

Запрос к внешнему API The Rick and Morty API средствами Node.js. Скрипт получает первую
страницу списка персонажей, выводит их имена со статусами и подробные данные о первом
персонаже. В методичке дан каркас функции, в котором не хватало вывода подробной
информации и самого вызова функции.

## Описание решения

```
Solution/
    getCharacter.js    запрос к API и вывод результата
    package.json       описание проекта и команда запуска
```

Зависимостей у проекта нет, поэтому `node_modules` рядом не появляется и `npm install` не
нужен. Запрос выполняется функцией `fetch`, которая встроена в Node.js начиная с
восемнадцатой версии, а разбор JSON умеет сам язык.

## Как запустить

Нужен Node.js не ниже 18 версии и работающий интернет: данные берутся с внешнего сайта.

```bash
npm start
```

или `node getCharacter.js`, это одно и то же. Проверял на Node.js 24.21.0.

## Разбор кода

Функция объявлена с `async`, и внутри неё стоят два `await`: первый ждёт ответа сервера,
второй разбора тела ответа.

```js
const response = await fetch(apiUrl);
```

Без `await` в переменной оказался бы сам промис, а не ответ, и обращение к `response.ok`
дало бы `undefined`. Сервер при этом ответил бы как обычно, но результат программа бы
потеряла.

Проверка `response.ok` нужна потому, что `fetch` считает ошибкой только сбой самого
соединения. Ответ с кодом 404 для него такой же нормальный результат, как и 200, поэтому
без этой проверки программа пошла бы разбирать страницу ошибки как список персонажей.
Выброшенное здесь исключение ловит тот же `try`, что и сетевые сбои:

```js
if (!response.ok) {
    throw new Error(`Ошибка HTTP! Статус: ${response.status}`);
}
```

Дописать самостоятельно надо было вывод подробной информации о первом персонаже. Первый
элемент массива `results` я взял напрямую, потому что страница всегда непустая, и вывел
три поля построчно:

```js
const first = characters[0];

console.log(`Имя: ${first.name}`);
console.log(`Вид: ${first.species}`);
console.log(`Происхождение: ${first.origin.name}`);
```

С происхождением есть тонкость: в ответе `origin` это не строка, а вложенный объект с
полями `name` и `url`. Если подставить его в строку целиком, в консоли окажется
`[object Object]`, поэтому берётся именно `origin.name`.

Второе, что требовалось дописать, это вызов функции. Он стоит последней строкой файла:

```js
fetchCharacters();
```

Возвращённый промис здесь никому не нужен: ошибки уже обработаны внутри самой функции
блоком `catch`, поэтому ни `await`, ни `.then()` не ставятся.

Отдельно про `characters.slice(0, 20)`. API отдаёт ровно двадцать персонажей на страницу,
так что срез ничего не отрезает. Он оставлен из методички и страхует вывод на случай, если
размер страницы на стороне API поменяется.

## Проверка обработки ошибок

Блок `catch` я проверил на двух случаях, подменяя адрес в копии файла.

| Что подменял | Что произошло | Сообщение |
| --- | --- | --- |
| `/character` на `/characterX` | сервер ответил кодом 404 | `Ошибка HTTP! Статус: 404` |
| домен на несуществующий | соединение не установилось | `fetch failed` |

Разница между этими случаями важная. В первом ответ пришёл, и ошибку создаёт сама
программа проверкой `response.ok`. Во втором запрос вообще не дошёл, и промис `fetch`
отклоняется сам. Оба пути приводят в один и тот же `catch`, программа не падает с
необработанным исключением, а печатает понятную строку.

## Теоретическая часть

**API** это набор правил, по которым одна программа обращается к другой. В веб-разработке
это чаще всего Web API: обмен идёт по протоколу HTTP, а адрес запроса указывает на нужный
ресурс. The Rick and Morty API построен в стиле REST, его ресурсы это персонажи
(`/character`), эпизоды (`/episode`) и локации (`/location`), а базовый адрес
`https://rickandmortyapi.com/api/`.

**Методы HTTP** различают назначение запроса: GET получение данных, POST добавление, PUT
обновление, DELETE удаление. Здесь нужен только GET, и `fetch` использует его по
умолчанию.

**Код статуса** сообщает исход запроса: 200 успешно, 404 ресурс не найден, 500 ошибка на
стороне сервера. Проверка `response.ok` это проверка попадания кода в диапазон 200-299.

**Асинхронность.** Сетевой запрос занимает время, и язык не простаивает в ожидании, а
продолжает выполнение. Результат представлен промисом, объектом, который обещает значение
позже. `async` перед функцией означает, что она всегда возвращает промис, а `await` внутри
неё приостанавливает выполнение до разрешения промиса, за счёт чего асинхронный код
выглядит как обычный последовательный.

**fetch** принимает адрес и возвращает промис с объектом `Response`. Сам объект содержит
статус и заголовки, а тело читается отдельными методами, тоже асинхронными. Метод
`.json()` читает тело и разбирает его как JSON, превращая в обычный объект JavaScript.

**JSON** это текстовый формат обмена данными на основе синтаксиса объектов JavaScript. У
этого API ответ состоит из двух частей: объект `info` с общим количеством записей и
ссылками на соседние страницы и массив `results` с самими персонажами, по двадцать на
страницу.

**try...catch** нужен потому, что при работе с сетью ошибка это нормальный исход: сервер
может быть недоступен, соединение обрывается. Код запроса ставится в `try`, а обработка
сбоя в `catch`, иначе необработанное исключение завершит процесс.

## Ответы на вопросы

Контрольных вопросов в методичке этого занятия нет, поэтому вопросы я составил по
теоретической части сам.

**1. Что такое API и что означает, что он построен в стиле REST?**

Это набор правил, по которым программы обмениваются данными. REST означает, что каждый
вид данных доступен по своему адресу, действие над ним задаётся методом HTTP, а сервер не
хранит состояние клиента между запросами.

**2. Какой метод HTTP используется в этой работе и почему его не пришлось указывать?**

GET, потому что данные только читаются. `fetch` подставляет этот метод по умолчанию,
когда вторым аргументом не передана настройка.

**3. Чем отличается промис от обычного возвращаемого значения?**

Обычное значение готово сразу, а промис это объект, который представляет результат, пока
ещё не полученный. У него три состояния: ожидание, успешное выполнение и отклонение.

**4. Что делают ключевые слова async и await?**

`async` объявляет функцию асинхронной, она всегда возвращает промис. `await` внутри такой
функции приостанавливает её выполнение до разрешения промиса и возвращает его значение.

**5. Почему нужна проверка response.ok, если ошибки уже ловит catch?**

`fetch` отклоняет промис только при сбое соединения. Ответ с кодом 404 или 500 для него
успешный результат, и без этой проверки программа начала бы разбирать страницу ошибки как
нормальные данные.

**6. Что возвращает метод .json() и почему перед ним стоит await?**

Он возвращает промис, который разрешается объектом JavaScript, полученным разбором тела
ответа. Чтение тела асинхронно, поэтому без `await` в переменной оказался бы промис, а не
данные.

**7. Как устроен ответ этого API?**

Это объект из двух полей. В `info` лежит общее количество записей, число страниц и ссылки
на следующую и предыдущую. В `results` массив персонажей, по двадцать штук на страницу.

**8. Почему происхождение персонажа выводится через origin.name, а не просто origin?**

Потому что `origin` это вложенный объект с полями `name` и `url`. При подстановке его в
строку целиком получилось бы `[object Object]`.

**9. Нужны ли этой программе сторонние библиотеки?**

Нет. Начиная с восемнадцатой версии `fetch` встроен в Node.js, а разбор JSON умеет сам
язык, поэтому зависимостей в `package.json` нет.

**10. Что произойдёт при запуске без интернета?**

Запрос не дойдёт до сервера, промис `fetch` будет отклонён, управление перейдёт в `catch`,
и программа напечатает сообщение об ошибке с текстом `fetch failed`, не прерываясь
аварийно.
