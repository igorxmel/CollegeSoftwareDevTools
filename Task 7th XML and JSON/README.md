# Практическое занятие №7. Представление информации в XML и JSON

Четыре небольших задания про два формата описания данных. Первые два это XML-документы:
сведения о книге и данные абонента телефонной линии. Третье и четвёртое про JSON:
описать те же данные, преобразовать их в объект JavaScript и вывести на страницу, а потом
разобрать готовую строку JSON и поработать с её полями.

```
Solution/

    subscriber.xml       задание 2, данные абонента телефонной линии
    index.html           задания 3 и 4, JSON и работа с объектом
    ПЗ-7_XML_JSON.docx   отчёт
```

Третье и четвёртое задания лежат на одной странице: оба про JSON, оба выводят результат в
элемент страницы, разносить их по двум файлам смысла не было. Листинги в отчёт
подтягиваются прямо из этих файлов при сборке, так что разойтись они не могут.

## Как запустить

Ничего устанавливать не нужно. XML-документы открываются двойным щелчком в любом браузере,
он показывает дерево элементов и заодно проверяет документ на корректность: если бы тег
остался незакрытым, вместо дерева была бы ошибка разбора.

`index.html` тоже открывается в браузере напрямую, без сервера. Внизу страницы два блока с
результатом, консоль при этом должна остаться пустой.

## Разбор решения

**Задание 1, книга.** Сведения описаны вложенными элементами. Автор разбит на фамилию и
инициалы отдельными тегами: так к ним можно обратиться по отдельности, например
отсортировать каталог по фамилии, а не разбирать строку целиком.

**Задание 2, абонент.** Здесь интереснее выбор между элементом и атрибутом. Серия и номер
паспорта записаны атрибутами одного элемента, потому что вместе они образуют один реквизит
и по отдельности не используются:

```xml
<паспорт серия="6009" номер="412344"/>
```

Адрес, наоборот, расписан вложенными элементами (город, улица, дом, квартира): каждую его
часть вполне может понадобиться прочитать саму по себе, например отобрать всех абонентов
одного города.

**Задание 3, JSON и вывод на страницу.** Те же данные о книге записаны в JSON, разобраны
методом `JSON.parse` и выведены в элемент `<pre>` перебором ключей объекта:

```js
const book = JSON.parse(bookJson);
let bookText = '';
for (const key in book) {
    bookText += key + ': ' + book[key] + '\n';
}
bookOutput.textContent = bookText;
```

Используется `textContent`, а не `innerHTML`: выводится обычный текст, и подставлять его
как разметку незачем.

**Задание 4, парсинг строки.** Разбирается строка `'{"name": "Иван", "age": 30}'`. Чтобы
было видно, что после разбора это полноценный объект, а не текст, на странице показан не
только результат, но и тип значения, обращение к полям через точку, арифметика над
возрастом и обратное преобразование через `JSON.stringify`.

## Теоретическая часть

**XML** это расширяемый язык разметки. Он описывает данные вложенными тегами, имена
которых придумывает сам разработчик. Документ обязан быть корректным: ровно один корневой
элемент, каждый открытый тег закрыт, вложенность не нарушена, значения атрибутов в
кавычках. В первой строке обычно стоит объявление с версией и кодировкой.

Значение в XML можно хранить двумя способами: содержимым элемента или атрибутом. Атрибуты
удобны для коротких служебных характеристик, элементы для самих данных.

**JSON** это текстовый формат обмена данными, построенный на синтаксисе объектов
JavaScript, но независимый от языка. Данные записываются парами «ключ и значение» в
фигурных скобках, списки в квадратных. Ключи и строковые значения всегда в двойных
кавычках, числа и логические значения без них, завершающая запятая недопустима. Типы
значений: строка, число, логическое значение, null, объект, массив.

Строку JSON превращает в объект метод `JSON.parse`, обратное преобразование делает
`JSON.stringify`. После разбора это обычный объект, к полям которого обращаются через
точку, а вывести содержимое на страницу можно через `textContent` или `innerHTML`
найденного элемента.

## Ответы на вопросы

**1. Каково назначение XML?**

XML предназначен для описания и хранения структурированных данных в виде, понятном и
человеку, и программе. Он не выводит данные на экран и не задаёт их оформление, а только
описывает структуру и смысл, поэтому используется для обмена данными между системами,
конфигурационных файлов и документов со сложной вложенностью.

**2. Каково назначение JSON?**

JSON решает ту же задачу обмена данными, но компактнее. Он построен на синтаксисе объектов
JavaScript, поэтому в веб-приложениях данные с сервера приходят обычно именно в нём: разбор
занимает одну строку кода и сразу даёт готовый объект.

**3. В чём отличие XML и JSON?**

XML описывает данные тегами и поддерживает атрибуты, пространства имён, комментарии и
проверку по схеме. JSON описывает данные парами «ключ и значение», атрибутов и
комментариев у него нет. XML многословнее, зато выразительнее; JSON короче и ближе к
структурам данных языков программирования.

**4. В чём состоит преимущество JSON перед XML?**

Он занимает меньше места, потому что имя поля пишется один раз, а не в открывающем и
закрывающем теге. Его разбор проще и быстрее, а результатом сразу становится объект языка,
тогда как XML приходится обходить через DOM. Синтаксис минимальный, поэтому его быстрее
читать и труднее сломать.

**5. В чём отличие XML от HTML?**

У HTML фиксированный набор тегов, и назначение его в том, чтобы показать документ в
браузере. В XML имена тегов придумывает разработчик, и назначение его в том, чтобы описать
данные, а не их вид. HTML прощает ошибки разметки, браузер отобразит страницу и с
незакрытым тегом, XML же обязан быть корректным, иначе анализатор откажется его читать.
