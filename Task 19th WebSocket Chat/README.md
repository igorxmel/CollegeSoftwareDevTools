# ПЗ №19. Работа с WebSocket

Чат покупателей и консультантов магазина Dream Sneakers на WebSocket: сервер на Node.js с библиотекой ws и клиентская страница с индикатором соединения, именами авторов и блоком уведомлений от магазина. Тема мини-проекта выбрана самостоятельно, как разрешает методичка.

## Описание решения

```
Solution/
    package.json
    server.js
    index.html
    style.css
    chat.js
```

Решение состоит из сервера и статической страницы. Сервер лежит в server.js и запускается командой npm start, страница открывается через любой статический сервер или напрямую из файла. Зависимость одна: библиотека ws, она записана в package.json.

Тема приложения продолжает магазин Dream Sneakers из предыдущих работ. Цвета, шрифты и скругления взяты из лендинга по веб-программированию, поэтому страница выглядит как часть того же магазина. Чат нужен покупателю, чтобы спросить консультанта о наличии и размере, а уведомления используются для новостей магазина: поступления, акции, изменение графика работы.

| Задание | Где выполнено |
| --- | --- |
| 1. Соединение и обмен между вкладками | server.js: connection и message, chat.js: connect |
| 2. Статус соединения | chat.js: setStatus, события open и close |
| 3. Имя пользователя | поле name в index.html, поле name в сообщении |
| 4. Уведомления | server.js: строка консоли уходит всем, chat.js: addNotice |
| 5. Мини-проект | весь чат Dream Sneakers, проверка пустых значений и отключения |

## Как запустить

Перейти в папку решения:

```
cd Solution
```

Установить зависимость:

```
npm install
```

Запустить сервер:

```
npm start
```

Сервер слушает порт 8080. Страницу index.html нужно открыть в двух вкладках, чтобы увидеть обмен сообщениями. Чтобы отправить уведомление, достаточно ввести текст в консоли с запущенным сервером и нажать Enter.

## Как это работает

### Сервер

Сервер принимает подключения и сразу рассылает всем число подключённых. Сообщения приходят в виде JSON, разбираются в try/catch, и если строка не разобралась, отправителю уходит сообщение с type error. Для сообщений чата сервер заново проверяет имя и текст: пустые значения и слишком длинные строки отклоняются. Проверка есть и на клиенте, но сервер не должен полагаться на неё, потому что запрос можно отправить в обход страницы.

Принятое сообщение сервер оформляет с временем и отправляет каждому клиенту, у которого readyState равен OPEN. Закрытые соединения пропускаются, иначе send вызвал бы ошибку. При отключении клиента срабатывает событие close, и сервер заново рассылает число подключённых.

Уведомления работают от консоли сервера. Каждая введённая в неё строка уходит всем клиентам с type notice. Так сервер может сообщить о новом поступлении или изменении расписания без участия покупателей.

### Клиент

Страница при загрузке открывает соединение и показывает статус: жёлтый «Подключение…», зелёный «Подключено» и красный «Отключено». Статус меняют события open и close. Пока соединение не открыто, кнопка отправки заблокирована. При закрытии соединения страница через три секунды пробует подключиться снова, поэтому после перезапуска сервера обновлять её вручную не нужно.

Перед отправкой проверяется, что имя не пустое и что в сообщении есть текст помимо пробелов. Если проверка не пройдена, под списком сообщений появляется пояснение, а на сервер ничего не уходит. Имена и тексты вставляются через textContent, а не через innerHTML, чтобы чужой текст не мог добавить на страницу разметку.

## Проверка

Сервер запускался командой npm start, страница открывалась в браузере. Клиенты эмулировались скриптом на ws, в браузере проверялась сама страница.

| Что проверялось | Результат |
| --- | --- |
| Два клиента, сообщение от первого | Сообщение получили оба клиента |
| Сообщение из пробелов | Сервер отвечает «Пустое сообщение не отправлено», в чат не попадает |
| Сообщение без имени | Сервер отвечает «Введите имя перед отправкой сообщения» |
| Строка, не являющаяся JSON | Сервер отвечает «Сообщение не удалось разобрать» и не падает |
| Строка в консоли сервера | Уведомление пришло всем подключённым клиентам |
| Отключение одного клиента | Второй клиент получил обновлённое число онлайн |
| Страница при запущенном сервере | Статус «Подключено», кнопка доступна |
| Остановка сервера при открытой странице | Статус «Отключено», кнопка заблокирована |
| Запуск сервера снова | Страница сама подключилась, статус «Подключено» |
| Пустое имя или текст на странице | Показывается пояснение, сообщение не отправляется |

## Теоретическая часть

WebSocket это протокол, который держит между браузером и сервером одно постоянное двустороннее соединение. После установки соединения данные могут передавать обе стороны в любой момент, и серверу не нужно ждать запроса клиента.

В обычной схеме HTTP клиент отправляет запрос и получает один ответ, после чего обмен заканчивается. Чтобы узнать о новом событии, страница вынуждена опрашивать сервер по таймеру. У WebSocket нет заголовков на каждое сообщение и нет повторных запросов, поэтому задержка меньше, а нагрузка ниже.

Соединение начинается как обычный HTTP-запрос с заголовком Upgrade: websocket. Если сервер согласен, он отвечает кодом 101 Switching Protocols, и дальше тот же TCP-канал используется уже по протоколу WebSocket. Адрес начинается с ws:// или с wss:// для защищённого соединения.

В браузере для этого есть класс WebSocket. У объекта четыре события: open срабатывает при установке соединения, message при получении данных, close при закрытии, error при ошибке. Отправляет данные метод send, а поле readyState показывает состояние: подключение, открыто, закрывается, закрыто.

В Node.js встроенного сервера WebSocket нет, поэтому используется библиотека ws. WebSocket.Server принимает подключения, на каждое приходит объект socket со своими событиями message и close. Все активные соединения хранятся в server.clients, по этому набору и делается рассылка всем.

Сообщение между клиентом и сервером передаётся строкой, поэтому структурированные данные упаковываются в JSON. В приложении у каждого сообщения есть поле type: chat для сообщений чата, notice для уведомлений, online для числа подключённых и error для отказа сервера. По этому полю клиент решает, как показать пришедшие данные.

## Ответы на вопросы

Вопросы взяты из методички.

**1. Что такое WebSocket?**

WebSocket это протокол, который создаёт между браузером и сервером постоянное двустороннее соединение. Данные передаются в обе стороны в любой момент, поэтому сервер может сам отправить сообщение клиенту.

**2. Чем WebSocket отличается от HTTP?**

HTTP работает по схеме запрос и ответ: сервер отвечает только тогда, когда его спросили, а потом соединение заканчивает обмен. WebSocket держит соединение открытым, и каждая сторона отправляет данные сама. Отдельных запросов и заголовков на каждое сообщение нет.

**3. Для чего используется библиотека ws?**

В Node.js нет встроенной реализации WebSocket-сервера. Библиотека ws принимает подключения, разбирает протокол, даёт события на сокетах и список клиентов для рассылки.

**4. Как устанавливается соединение между браузером и сервером?**

Браузер отправляет обычный HTTP-запрос с заголовком Upgrade: websocket. Сервер отвечает кодом 101 Switching Protocols, после чего тот же канал работает как WebSocket. В коде достаточно создать объект new WebSocket с адресом ws://.

**5. Какие события WebSocket используются на клиенте?**

open при установке соединения, message при получении данных, close при его закрытии и error при ошибке. В приложении open и close переключают индикатор статуса, а message разбирает пришедший JSON.

**6. Как сервер получает сообщения от клиента?**

На каждом сокете подписываются на событие message. Данные приходят в виде буфера, поэтому перед разбором их переводят в строку методом toString. В приложении строка затем разбирается как JSON.

**7. Как отправить сообщение всем подключённым клиентам?**

Нужно перебрать server.clients и вызвать send у каждого клиента, у которого readyState равен WebSocket.OPEN. Проверка нужна, чтобы не отправлять данные в закрытое соединение. В приложении это функция broadcast.

**8. В каких веб-приложениях полезен обмен данными в реальном времени?**

В чатах и мессенджерах, онлайн-играх, системах уведомлений, панелях мониторинга и совместных редакторах. В магазине это чат с консультантом и оповещения о новом поступлении или акции.
