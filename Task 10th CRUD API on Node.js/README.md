# Практическое занятие №10. Развёртывание web-сервера с применением Node.js

API-сервер на Node.js и Express, который умеет все четыре CRUD-операции над хранилищем в
памяти. Хранилище это массив объектов с именем и возрастом. В методичке дан каркас
сервера, в котором готов только маршрут добавления, остальные четыре надо было написать
самому.

## Описание решения

```
Solution/
    index.js        сервер и все шесть маршрутов
    package.json    зависимости и команда запуска
```

Данные живут в обычном массиве внутри модуля, без базы. Это значит, что после перезапуска
сервера хранилище возвращается к исходным четырём записям: всё, что добавлено за время
работы, теряется. Для учебного API так и задумано, постоянное хранение в задании не
требуется.

## Как запустить

Нужен Node.js. Зависимости ставятся один раз:

```bash
npm install
```

Запуск:

```bash
npm start
```

или `node index.js`, это одно и то же. В консоли появится «Сервер запущен на
http://localhost:3000». Останавливается сервер через Ctrl+C.

Проверял на Node.js 24.14.0 и Express 5.3.0.

Про порт стоит сказать отдельно: в коде из методички стоит 3000, и сервер печатает именно
его, а в списке запросов для Postman указан 3003. Я оставил 3000, как в самом коде. Если
понадобится 3003, меняется одна строка в начале файла.

## Маршруты

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | `/start` | отдаёт строку «Привет мир» |
| GET | `/data` | возвращает все записи |
| POST | `/data` | добавляет запись, отвечает кодом 201 |
| PUT | `/data/:id` | обновляет запись по id |
| DELETE | `/data/:id` | удаляет запись по id |

PUT и DELETE на несуществующий id отвечают кодом 404 и сообщением об ошибке. В задании
этого прямо не сказано, но без проверки первый же запрос с чужим id либо молча ничего не
сделал бы, либо уронил сервер обращением к несуществующему элементу массива.

Текст ответа `/start` в методичке назван дважды и по-разному: в комментарии к маршруту
«Привет мир», а в списке запросов для Postman «Hello World». Я взял первый вариант, он
стоит там, где формулируется само требование.

## Разбор кода

Строка `app.use(express.json())` подключает промежуточный обработчик, который читает тело
запроса и разбирает его как JSON. Без него `req.body` остаётся пустым, и POST с PUT
работать не будут.

Поиск записи вынесен в отдельную функцию, потому что нужен и в PUT, и в DELETE:

```js
function findIndexById(rawId) {
    const id = Number(rawId);
    return storages.findIndex((item) => item.id === id);
}
```

Преобразование в число здесь обязательно. Часть адреса приходит строкой, а `id` в
хранилище число, и строгое сравнение `"1" === 1` даёт ложь, так что без приведения ни одна
запись никогда бы не нашлась.

Выдачу идентификаторов я поменял, и это единственное отступление от кода методички. Там
новый id считался как `storages.length + 1`. Такой способ ломается после первого же
удаления: записей становится меньше, длина массива уменьшается, и следующая добавленная
запись получает номер, который уже занят. Дальше PUT и DELETE по этому id работали бы с
первой попавшейся из двух записей. Поэтому заведён отдельный счётчик:

```js
let nextId = storages.length + 1;
```

Он только растёт и при удалении не сдвигается. Сценарий я специально проверил: удалил
запись, добавил новую, дубликатов не появилось.

В PUT обновляются только те поля, которые пришли в запросе:

```js
if (name !== undefined) {
    storages[index].name = name;
}
```

Иначе запрос, в котором передан только возраст, затёр бы имя значением `undefined`.

DELETE удаляет через `splice` и возвращает удалённую запись. Так по ответу видно, что
именно пропало, а не просто «готово».

## Проверка эндпоинтов

Postman я не ставил, запросы выполнял из браузера методом `fetch`: это те же самые
HTTP-запросы с теми же методами, заголовками и телом. Сценарий из методички целиком:

| Запрос | Код | Ответ |
| --- | --- | --- |
| `GET /start` | 200 | `Привет мир` |
| `GET /data` | 200 | четыре исходные записи |
| `POST /data` с `{"name": "Maria", "age": 20}` | 201 | `{"id":5,"name":"Maria","age":20}` |
| `PUT /data/1` с `{"name": "John Updated", "age": 16}` | 200 | `{"id":1,"name":"John Updated","age":16}` |
| `DELETE /data/2` | 200 | `{"id":2,"name":"Mike","age":16}` |
| `GET /data` | 200 | записи 1, 3, 4, 5, запись 2 пропала |

Отдельно проверил то, что в сценарий не входит:

| Запрос | Код | Что проверялось |
| --- | --- | --- |
| `POST /data` сразу после удаления | 201 | новый id равен 6, совпадений нет |
| `PUT /data/999` | 404 | несуществующий id |
| `DELETE /data/999` | 404 | то же для удаления |
| `PUT /data/abc` | 404 | id не число |
| `PUT /data/3` только с полем age | 200 | имя не затёрлось |

## Теоретическая часть

**Node.js** это среда выполнения JavaScript вне браузера, построенная на движке V8. Её
модель ввода-вывода неблокирующая: вместо того чтобы ждать завершения операции, программа
продолжает работу и возвращается к результату позже. За счёт этого один процесс
обслуживает много одновременных соединений, что и нужно веб-серверу.

**Express** это минималистичный фреймворк поверх встроенных возможностей Node.js. Он берёт
на себя маршрутизацию, разбор запросов и формирование ответов, а также поддерживает
middleware, промежуточные функции, через которые запрос проходит до попадания в
обработчик.

**Middleware** это функция, которая получает запрос и ответ до основного обработчика и
может их изменить. `express.json()` как раз такая: она читает тело запроса и кладёт
разобранный объект в `req.body`.

**Маршрут** складывается из метода и пути. `GET /data` и `POST /data` это два разных
маршрута при одинаковом адресе. Часть пути можно объявить параметром через двоеточие:
в `/data/:id` значение после слэша попадает в `req.params.id`.

**CRUD** это четыре базовые операции над данными: Create создание, Read чтение, Update
изменение, Delete удаление. По HTTP им соответствуют POST, GET, PUT и DELETE.

**Коды ответа** сообщают клиенту, чем кончился запрос: 200 успешно, 201 ресурс создан,
404 не найден, 500 ошибка на сервере.

## Ответы на вопросы

Контрольных вопросов в методичке этого занятия нет, поэтому вопросы я составил по
теоретической части сам.

**1. Что такое Node.js и чем он отличается от браузерного JavaScript?**

Среда выполнения JavaScript на сервере. В отличие от браузера, здесь нет DOM и окна, зато
есть доступ к файловой системе, сети и процессам операционной системы. Поэтому на Node.js
пишут серверы и утилиты, а не интерфейсы.

**2. Для чего нужен Express, если сервер можно написать на модуле http?**

Express избавляет от ручного разбора адреса и метода запроса. На чистом `http` обработчик
один на все адреса, и маршрутизацию пришлось бы писать самому, а здесь каждый маршрут
объявляется отдельной строкой.

**3. Что такое middleware и зачем в этой работе нужен express.json()?**

Промежуточная функция, через которую проходит запрос до основного обработчика.
`express.json()` читает тело запроса и разбирает его как JSON, складывая результат в
`req.body`. Без неё тело POST и PUT осталось бы непрочитанным.

**4. Что такое CRUD и каким методам HTTP соответствуют его операции?**

Четыре базовые операции над данными: создание, чтение, изменение и удаление. Им
соответствуют POST, GET, PUT и DELETE.

**5. Как передать серверу параметр в адресе маршрута?**

Объявить его в пути через двоеточие, например `/data/:id`, и читать из `req.params`.
Значение всегда приходит строкой, поэтому перед сравнением с числовым полем его надо
преобразовать.

**6. Чем отличается тело запроса от параметра в адресе?**

Параметр это часть адреса, он короткий и обычно указывает, с какой записью работать. Тело
это отдельный блок данных, он передаётся при POST и PUT и содержит сами значения полей.
У GET и DELETE тела, как правило, нет.

**7. Почему POST отвечает кодом 201, а не 200?**

201 означает, что в результате запроса создан новый ресурс. Это точнее обычного 200: по
одному коду ответа клиент понимает, что запись действительно появилась.

**8. Что произойдёт при запросе к несуществующему id и как это обработано?**

Поиск вернёт −1, и дальнейшее обращение по этому индексу привело бы к ошибке. В обоих
маршрутах стоит проверка, которая возвращает код 404 и сообщение, не трогая хранилище.

**9. Почему нельзя считать новый идентификатор как длина массива плюс один?**

После удаления записи длина уменьшается, и следующая добавленная получит уже занятый
номер. Два объекта с одинаковым id сломают PUT и DELETE: они найдут первый попавшийся.
Поэтому используется счётчик, который только растёт.

**10. Где хранятся данные этого API и что с ними происходит при перезапуске?**

В обычном массиве в оперативной памяти процесса. При перезапуске сервера модуль
выполняется заново, и хранилище возвращается к четырём исходным записям. Для постоянного
хранения понадобилась бы база данных или файл.
