# ПЗ №18. Разработка веб-приложения на React Router

Одностраничное приложение с динамической маршрутизацией и собственной серверной частью. Тема приложения выбрана самостоятельно, как разрешает методичка: каталог кроссовок Dream Sneakers. Клиент на React получает товары с API на Express, показывает список, карточку товара, категории и страницу 404.

## Описание решения

```
Solution/
    index.html
    package.json
    vite.config.js
    src/
        main.jsx
        App.jsx
        api.js
        index.css
        App.css
        components/
            Navbar.jsx
            Navbar.css
            Footer.jsx
            Footer.css
            ProductCard.jsx
            ProductCard.css
        pages/
            Home.jsx
            ProductsList.jsx
            ProductDetail.jsx
            Categories.jsx
            CategoryProducts.jsx
            About.jsx
            NotFound.jsx
            pages.css
    server/
        package.json
        data.js
        index.js
```

Клиент и сервер разделены по папкам. В `src/pages` лежат страницы, которые соответствуют маршрутам, в `src/components` находятся повторно используемые части: навигация, подвал и карточка товара. `src/api.js` собирает все запросы к API в одном месте, поэтому компоненты не работают с `fetch` напрямую и одинаково обрабатывают ошибки. Серверная часть вынесена в `server` и запускается отдельным процессом.

`vite.config.js` перенаправляет запросы с `/api` на `http://localhost:3001`. В разработке клиент обращается к относительному адресу, а Vite проксирует его на Express. На сервере при этом включен CORS, как требует задание, поэтому API можно вызвать и напрямую с другого origin.

## Как запустить

Перейти в папку решения:

```
cd Solution
```

Установить зависимости клиента:

```
npm install
```

Установить зависимости сервера:

```
cd server
npm install
cd ..
```

Запустить клиент и сервер одной командой:

```
npm run dev
```

Скрипт `dev` использует `concurrently` и запускает оба процесса. Клиент открывается на `http://localhost:5173`, API работает на `http://localhost:3001`. Проверить production-сборку клиента можно командой:

```
npm run build
```

## Серверная часть

Данные хранятся в массиве внутри `server/data.js`. Базы данных в задании нет, поэтому после перезапуска сервера список возвращается к исходным шести товарам. У каждого товара поля `id`, `title`, `category`, `price` и `description`.

| Метод | Адрес | Что делает |
| --- | --- | --- |
| GET | `/api/products` | возвращает все товары, поддерживает `?category=` |
| GET | `/api/products/:id` | возвращает один товар или 404 |
| GET | `/api/categories` | возвращает список категорий |
| POST | `/api/products` | создает товар и отвечает кодом 201 |
| PUT | `/api/products/:id` | обновляет переданные поля |
| PATCH | `/api/products/:id` | частично обновляет товар |
| DELETE | `/api/products/:id` | удаляет товар |

Сервер подключает два middleware. `cors()` разрешает запросы с другого origin, а `express.json()` разбирает тело запросов POST, PUT и PATCH. Без второго middleware `req.body` остался бы пустым.

Идентификаторы выдаются отдельным счетчиком, который только растет. Если считать новый номер как длину массива плюс один, то после удаления товара следующая запись получит уже занятый идентификатор. Счетчик этой проблемы не имеет.

При создании товара проверяется, что переданы все поля, а цена приводится к числу. Если обязательное поле отсутствует, сервер отвечает кодом 400. Если товар с указанным идентификатором не найден, GET, PUT, PATCH и DELETE отвечают кодом 404 с сообщением «Товар не найден».

Основные обработчики выглядят так:

```js
app.get("/api/products", (req, res) => {
    const { category } = req.query;

    const result = category
        ? products.filter((product) => product.category === category)
        : products;

    res.json(result);
});

app.get("/api/products/:id", (req, res) => {
    const product = findProduct(req.params.id);

    if (!product) {
        return res.status(404).json({ message: "Товар не найден" });
    }

    res.json(product);
});
```

Параметр `:id` всегда приходит строкой, поэтому перед сравнением он приводится к числу. Иначе строгое сравнение с числовым `id` не нашло бы ни одного товара.

## Маршруты клиента

`BrowserRouter` стоит в `main.jsx` и оборачивает все приложение. В `App.jsx` описаны маршруты через `Routes` и `Route`:

```jsx
<Routes>
    <Route path="/" element={<Home />} />
    <Route path="/products" element={<ProductsList />} />
    <Route path="/products/:productId" element={<ProductDetail />} />
    <Route path="/categories" element={<Categories />} />
    <Route path="/categories/:categoryName" element={<CategoryProducts />} />
    <Route path="/about" element={<About />} />
    <Route path="*" element={<NotFound />} />
</Routes>
```

| Путь | Компонент | Что показывает |
| --- | --- | --- |
| `/` | `Home` | главная страница с описанием и ссылками |
| `/products` | `ProductsList` | все товары и фильтр по категории |
| `/products/:productId` | `ProductDetail` | один товар по идентификатору |
| `/categories` | `Categories` | список категорий |
| `/categories/:categoryName` | `CategoryProducts` | товары выбранной категории |
| `/about` | `About` | информация о приложении |
| `*` | `NotFound` | страница 404 |

Динамические части адреса объявлены через двоеточие. В компоненте они читаются хуком `useParams`. Для страницы товара это `productId`, для страницы категории `categoryName`.

```jsx
const { productId } = useParams();
```

На странице товара используется `useNavigate`. Кнопка «Назад к списку» при успешной загрузке вызывает `navigate(-1)`, то есть возвращает на предыдущую страницу. Если товар не найден, кнопка ведет прямо на `/products`, потому что возвращаться назад в этом случае может быть некуда.

```jsx
const navigate = useNavigate();

<button type="button" onClick={() => navigate(-1)}>
    Назад к списку
</button>
```

Навигация в шапке сделана через `NavLink`. Он сам добавляет класс активной ссылки, поэтому текущий раздел подсвечивается. Для главной страницы указан `end`, иначе она считалась бы активной на всех маршрутах.

## Фильтрация и useLocation

Фильтр на странице товаров хранится не в обычном состоянии, а в параметрах адреса. Для этого используется `useSearchParams`:

```jsx
const [searchParams, setSearchParams] = useSearchParams();
const category = searchParams.get("category") || "";

function handleCategoryChange(event) {
    const value = event.target.value;

    if (value) {
        setSearchParams({ category: value });
    } else {
        setSearchParams({});
    }
}
```

При выборе категории адрес меняется на `/products?category=running`, а эффект, который зависит от `category`, заново запрашивает товары с сервера. Если фильтр сбросить, параметр исчезает и загружается полный список. Такой подход удобен тем, что ссылку с фильтром можно скопировать или обновить страницу, и состояние сохранится.

Подвал показывает текущий маршрут через `useLocation`:

```jsx
const location = useLocation();

<footer>
    <span>Текущий путь: {location.pathname}</span>
    <span>Параметры запроса: {location.search || "нет"}</span>
</footer>
```

`location.pathname` содержит путь без query-строки, а `location.search` содержит ее вместе со знаком вопроса. На главной странице search пустой, поэтому выводится «нет».

## Теоретическая часть

SPA, или одностраничное приложение, загружает HTML один раз, а дальше меняет содержимое средствами JavaScript. Переход между разделами не вызывает полную перезагрузку страницы. Это быстрее и позволяет сохранять состояние, но требует отдельной библиотеки маршрутизации.

`BrowserRouter` использует History API браузера. Он перехватывает переходы по ссылкам и меняет адрес через `pushState`, не отправляя запрос на сервер. При обычной перезагрузке такого адреса сервер должен вернуть тот же `index.html`, иначе получится 404. Vite dev server делает это автоматически, а в production для этого нужна настройка сервера.

`Routes` выбирает первый подходящий `Route` для текущего адреса. `Route` связывает путь с компонентом. Путь может содержать параметры, которые начинаются с двоеточия, например `/products/:productId`. Значение параметра доступно через `useParams`.

`Link` и `NavLink` заменяют обычные ссылки `<a>` внутри приложения. Они не перезагружают страницу, а передают новый путь роутеру. `NavLink` дополнительно умеет сообщать, активен ли маршрут, что удобно для меню.

Хуки маршрутизации дают доступ к разным частям состояния. `useNavigate` возвращает функцию для программного перехода. `useLocation` возвращает текущий объект location с путем и query-строкой. `useSearchParams` работает как `useState`, но хранит значение в адресной строке.

`fetch` возвращает промис, поэтому запросы пишутся в асинхронной функции с `await`. Ошибки сети и ответы с кодом 4xx или 5xx нужно обрабатывать отдельно: `fetch` не считает их исключением, он просто возвращает ответ с соответствующим статусом. В этом приложении проверка `response.ok` превращает такой ответ в исключение, а компонент показывает сообщение об ошибке.

Express это минималистичный серверный фреймворк для Node.js. Он распределяет запросы по методу и пути, а middleware обрабатывают общие задачи: разбор JSON, разрешение CORS, логирование. CORS нужен, когда клиент и сервер находятся на разных origin, иначе браузер заблокирует чтение ответа.

## Ответы на вопросы

В методичке контрольных вопросов нет, поэтому вопросы составлены по теоретической части.

**1. Чем SPA отличается от многостраничного приложения?**

В многостраничном приложении каждый переход запрашивает у сервера новую HTML-страницу. В SPA сервер отдает один HTML-документ, а дальше маршрутизацией занимается JavaScript. Меняется только содержимое страницы, браузер не перезагружает документ целиком. За счет этого переходы быстрее, но появляются дополнительные требования к маршрутизации и загрузке данных.

**2. Зачем нужен BrowserRouter и что он делает с адресной строкой?**

`BrowserRouter` связывает React Router с History API браузера. Он слушает изменения адреса, передает их в `Routes` и позволяет менять адрес через `pushState` без перезагрузки. При нажатии на `Link` адресная строка обновляется, но запрос на сервер не уходит.

**3. Чем Route отличается от Routes?**

`Route` описывает одно правило: какой путь и какой компонент ему соответствуют. `Routes` это контейнер, который выбирает из вложенных `Route` наиболее подходящее совпадение для текущего адреса. Без `Routes` все подходящие маршруты могли бы отрисоваться одновременно.

**4. Как получить параметр из адреса и чем useParams удобнее разбора pathname?**

Параметр объявляется в пути через двоеточие, например `/products/:productId`. В компоненте его значение читается через `useParams`, который возвращает объект с параметрами. Это удобнее ручного разбора `location.pathname`, потому что React Router уже учитывает структуру маршрута и возвращает готовые значения.

**5. Для чего нужны useNavigate и useLocation?**

`useNavigate` возвращает функцию для программного перехода: после сохранения формы, при ошибке или по нажатию кнопки. `useLocation` возвращает текущий адрес и query-строку. В этом приложении `useLocation` используется в подвале, чтобы показать текущий путь.

**6. Как useSearchParams помогает хранить состояние фильтра в URL?**

`useSearchParams` читает и записывает query-параметры адреса. В приложении выбранная категория хранится как `?category=running`. При изменении фильтра обновляется адрес, а эффект заново запрашивает данные. Если страницу обновить или отправить ссылку другому человеку, фильтр сохранится.

**7. Почему запросы оборачивают в try/catch и какие состояния нужно показать пользователю?**

Сеть может быть недоступна, сервер может вернуть ошибку, а ответ может оказаться не таким, как ожидается. `try/catch` позволяет не оставить интерфейс в подвешенном состоянии. Пользователю нужно показать хотя бы три состояния: загрузка, успешный результат и ошибка. В приложении для этого есть отдельные переменные `loading` и `error`.

**8. Зачем нужен CORS и почему без него браузер блокирует запрос?**

CORS это механизм, который сообщает браузеру, каким origin разрешено читать ответ сервера. Если клиент на `localhost:5173` обращается к API на `localhost:3001`, это разные origin. Без заголовков CORS браузер получит ответ, но не отдаст его JavaScript-коду. Middleware `cors()` добавляет нужные заголовки.

**9. Что произойдет при перезагрузке страницы /products/1?**

Vite dev server вернет `index.html` для любого пути, поэтому приложение загрузится и React Router разберет адрес. В production-сборке нужен сервер, который тоже отдает `index.html` для всех маршрутов SPA. Иначе запрос `/products/1` попадет на сервер как запрос файла и вернет 404.
