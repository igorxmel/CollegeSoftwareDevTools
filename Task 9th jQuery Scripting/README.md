# Практическое занятие №9. Создание сценариев с использованием jQuery

Пять небольших заданий на библиотеку jQuery: обработка событий, переключение класса,
плавное раскрытие блока, проверка формы и список задач с добавлением, отметкой выполнения
и удалением. Все пять собраны на одной странице, разделами.

## Описание решения

```
Solution/
    index.html    разметка всех пяти заданий
    styles.css    оформление, в том числе класс active и скрытый блок
    script.js     сценарии, по одному блоку на задание
```

Методичка просит создать `index.html` в первом задании и дальше про новые файлы ничего не
говорит, поэтому остальные четыре легли на ту же страницу отдельными секциями. Так их
удобнее показывать: всё открывается одним файлом, ничего не надо переключать.

Стили и сценарии вынесены в отдельные файлы, а не в теги внутри страницы. Пять заданий в
одном `index.html` иначе превратились бы в кашу из разметки, CSS и JavaScript вперемешку.

jQuery подключён через CDN, как требует методичка, поэтому для работы страницы нужен
интернет.

## Как запустить

Файл открывается в браузере напрямую, двойным щелчком по `index.html`, сервер не нужен.

Если хочется отдать страницу по HTTP, из папки `Solution` подойдёт встроенный сервер
Python:

```bash
python -m http.server 8936
```

Дальше http://localhost:8936. Проверял обоими способами, jQuery подтянулся версии 3.7.1.

## Разбор заданий

Весь код обёрнут в `$(function () { ... })`. Это короткая запись `$(document).ready()`:
содержимое выполняется, когда браузер уже разобрал разметку. Без неё скрипт, подключённый
в `<head>`, искал бы элементы, которых ещё нет.

**Задание 1.** Заголовок переключается между двумя состояниями. Текущий текст читается
методом `.text()` без аргумента, новый ставится тем же методом с аргументом. Обе строки
вынесены в константы: иначе условие сравнивает заголовок с литералом, и при правке текста
в одном месте переключение молча ломается.

**Задание 2.** Оформление карточки описано классом `.card.active` в CSS, а скрипт только
добавляет и убирает его одной строкой:

```js
$("#card").toggleClass("active");
```

Менять цвета через `.css()` здесь было бы хуже: оформление уехало бы из таблицы стилей в
сценарий, и вернуть исходный вид пришлось бы вторым набором `.css()`.

**Задание 3.** Блок скрыт в CSS правилом `display: none`, дальше им управляет
`.slideToggle(300)`, где 300 это длительность анимации в миллисекундах. Текст кнопки
переключается по её текущему значению, так что надпись всегда соответствует тому, что
произойдёт при нажатии.

**Задание 4.** Обработчик висит на событии `submit` формы, а не на клике по кнопке: так он
сработает и при отправке клавишей Enter. Первым делом вызывается `event.preventDefault()`,
иначе браузер перезагрузит страницу и сообщение исчезнет. Значения полей берутся через
`.val()` и обрезаются `.trim()`, поэтому строка из одних пробелов считается незаполненной.

**Задание 5.** Самое объёмное. Задача добавляется в список через `.append()`, причём
элементы создаются по отдельности, а текст ставится методом `.text()`:

```js
const task = $("<li>");
const text = $("<span>").text(taskText);
const deleteButton = $("<button>").text("Удалить").addClass("deleteButton");
task.append(text, deleteButton);
```

Если вместо этого собрать строку HTML и вставить её, то введённые пользователем теги
выполнятся как разметка. Я проверил: при вводе `<b>тег</b>` задача показывается именно
такой строкой, а жирного текста внутри не появляется.

Обработчики отметки и удаления повешены на сам список, а не на задачи:

```js
$("#taskList").on("click", "span", function () { ... });
```

Это делегирование. Задач при загрузке страницы ещё нет, и обычный обработчик вешать было
бы не на что, а новые задачи появляются уже после. Список же существует всегда, и события
от своих потомков он получает.

В обработчике удаления стоит `event.stopPropagation()`. Без него клик по кнопке всплыл бы
до элемента списка и заодно отметил бы задачу выполненной прямо перед удалением.

## Теоретическая часть

**jQuery** это библиотека JavaScript, которая упрощает работу с DOM, обработку событий,
изменение стилей и анимацию. Она не заменяет JavaScript, а даёт набор готовых методов для
частых операций: то, что на чистом языке пишется как
`document.querySelector("#message").textContent = "Привет!"`, здесь становится
`$("#message").text("Привет!")`.

**Подключение.** Чаще всего через CDN, тегом `<script>` с адресом библиотеки. Подключать
её нужно до скриптов, которые пользуются её методами, иначе `$` ещё не существует.

**Селекторы** повторяют синтаксис CSS: `$("#title")` ищет по идентификатору, `$(".item")`
по классу, `$("p")` по тегу, `$(".menu a")` по вложенности.

**Методы работы с содержимым.** `.text()` читает и задаёт текст, `.html()` то же самое для
разметки, `.val()` работает со значением поля формы, `.append()` добавляет содержимое,
`.empty()` очищает элемент. Для обычного текста берут `.text()`, а `.html()` применяют
осторожно, особенно к данным, которые ввёл пользователь.

**События** обрабатывает метод `.on()`. Частые события: `click`, `dblclick`, `mouseenter`,
`mouseleave`, `input`, `change`, `submit`, `keydown`. Внутри обработчика `$(this)` это
элемент, на котором событие произошло.

**Стили** меняет `.css()`, одним свойством или объектом сразу. Для готового оформления
удобнее классы: `.addClass()`, `.removeClass()` и `.toggleClass()`.

**Эффекты.** `.hide()` и `.show()` переключают видимость мгновенно, `.toggle()` меняет её
на противоположную. Плавные варианты: `.fadeIn()` и `.fadeOut()` по прозрачности,
`.slideUp()`, `.slideDown()` и `.slideToggle()` по высоте.

## Ответы на вопросы

**1. Что такое jQuery и для каких задач применяется эта библиотека?**

Библиотека JavaScript для работы с HTML-документом: поиск элементов, изменение их
содержимого и стилей, обработка событий, анимация и асинхронные запросы. Нужна, чтобы
частые операции писались короче и одинаково работали в разных браузерах.

**2. Каким способом можно подключить jQuery к HTML-документу?**

Тегом `<script>` с адресом CDN либо ссылкой на скачанный локально файл библиотеки. В этой
работе использован CDN, как требует методичка. Подключение должно идти до собственных
скриптов.

**3. Для чего используется конструкция $(document).ready()?**

Она откладывает выполнение кода до момента, когда браузер разобрал разметку страницы.
Без неё скрипт может обратиться к элементу, которого ещё нет, и получить пустую выборку.
Короткая запись той же конструкции это `$(function () { ... })`.

**4. Чем отличаются селекторы $("#element") и $(".element")?**

Первый ищет элемент по идентификатору и находит не больше одного, потому что идентификатор
на странице уникален. Второй ищет по классу и возвращает все подходящие элементы, сколько
бы их ни было.

**5. Как с помощью jQuery изменить текст HTML-элемента?**

Методом `.text()` с аргументом: `$("#title").text("Новый текст")`. Тот же метод без
аргумента возвращает текущий текст, на этом построено переключение заголовка в первом
задании.

**6. Для чего предназначен метод .on()?**

Он привязывает обработчик к событию выбранных элементов. Вторым аргументом ему можно
передать селектор, и тогда получится делегирование: обработчик висит на родителе, а
срабатывает на подходящих потомках, включая появившихся позже.

**7. В чём различие между методами .hide(), .show() и .toggle()?**

`.hide()` скрывает элемент, `.show()` показывает, `.toggle()` переключает: скрывает
видимый и показывает скрытый. Первые два задают состояние явно, третий зависит от
текущего.

**8. Для чего используется метод .toggleClass()?**

Он добавляет класс, если его на элементе нет, и убирает, если есть. Это удобно, когда
оформление описано в CSS, а переключать надо только его наличие, как с классом `active`
во втором задании.

**9. Как получить значение текстового поля формы?**

Методом `.val()` без аргумента. Он же с аргументом записывает новое значение, например
`$("#taskInput").val("")` очищает поле после добавления задачи.

**10. Для чего применяется event.preventDefault() при обработке формы?**

Он отменяет действие браузера по умолчанию. Для формы это отправка данных и перезагрузка
страницы, после которой весь результат работы сценария пропал бы.

**11. Что такое делегирование событий и почему оно полезно при работе с динамическими
элементами?**

Обработчик вешается не на сами элементы, а на их общего родителя, и событие ловится при
всплытии с проверкой селектора. Полезно потому, что элементы, созданные после загрузки
страницы, обычным обработчиком не покрываются: в момент привязки их ещё не существовало.
В списке задач все задачи появляются динамически, и без делегирования пришлось бы вешать
обработчики на каждую заново.

**12. Какие преимущества и ограничения имеет jQuery по сравнению с современным
JavaScript?**

Преимущества: компактный синтаксис, короткая работа с DOM и событиями, готовые эффекты и
анимация, удобная работа с формами и AJAX. Ограничения: это дополнительная зависимость,
которую надо загружать, а большинство задач сегодня решается средствами самого языка
(`querySelector`, `classList`, `fetch`). Актуальна она в основном там, где уже используется
в существующем проекте.
