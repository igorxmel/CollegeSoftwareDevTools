# Практическое занятие №8. Отладка модулей и обработка исключений

Программа идёт по аргументу с заданным шагом, считает значения функции и останавливается,
когда проходит характерную точку графика. Вариант 6: функция Y(X) = x² − eˣ, характерной
считается точка, в которой она равна −10. Работа не столько про сам поиск, сколько про то,
как разложить программу на модули, расставить в них обработку исключений и составить
тесты, которые проверяют каждую ветвь.

## Описание решения

```
Solution/
    Main.java                      управляющий модуль
    InputModule.java               ввод вещественных чисел
    FunctionModule.java            функция варианта и её отклонение от уровня
    SearchModule.java              проход по аргументу и уточнение точки
    OutputModule.java              заголовок, протокол, результат, ошибки
    SearchException.java           общий предок исключений поиска
    InvalidStepException.java      шаг задан неположительным
    PointNotFoundException.java    точка не встретилась за отведённые шаги
    flowchart.png                  блок-схема для отчёта
    flowchart.drawio               она же, открывается в draw.io
    run-example.txt                протокол работы при X0 = 0 и h = 0,1
    ПЗ-8_Отладка.docx              отчёт
```

Разбивка на модули повторяет шестую работу: отдельно ввод, отдельно вычисления, отдельно
вывод, сверху управляющий класс, который их связывает. Польза от этого видна как раз на
отладке: когда тест падает, сразу понятно, в каком модуле смотреть, а подменить функцию
варианта можно правкой одного файла.

Три класса исключений вместо одного потому, что неположительный шаг и ненайденная точка
это разные ситуации и реакция на них разная. Общий предок нужен, чтобы при желании ловить
обе одной строкой.

## Как запустить

Нужен установленный JDK, проверяется командой `java -version`. Сборка и запуск из папки
`Solution`:

```bash
javac -encoding UTF-8 -d build *.java
```

```bash
java -cp build Main
```

Ключ `-encoding UTF-8` обязателен: в исходниках русские строки, и без него компилятор на
Windows читает файлы в кодировке системы и ругается на нечитаемые символы.

Программа спросит начальное значение X0 и шаг h, после чего напечатает протокол и
координаты найденной точки. Для первого запуска подойдут 0 и 0,1. Проверял на Java 25.0.2.

Если понадобится перенаправить вывод в файл, добавь `-Dstdout.encoding=UTF-8`, иначе в
файл уйдёт кодировка консоли и кириллица превратится в мусор. В самом терминале всё
печатается нормально и без этого ключа.

## Разбор алгоритма

Характерная точка это решение уравнения Y(X) = −10. Вместо того чтобы сравнивать значение
функции с уровнем напрямую, программа работает с отклонением D = Y(X) − (−10): тогда
искомая точка это просто нуль отклонения.

Проход идёт по сетке X0, X0 + h, X0 + 2h и так далее. На каждом шаге сравниваются
отклонения в соседних узлах, и если произведение Dпр · D оказалось не больше нуля, значит
между ними отклонение сменило знак, то есть точка пройдена:

```java
if (dPrev * d <= 0) {
    double root = refine(xPrev, x);
    return new Result(root, FunctionModule.value(root), step, trace);
}
```

Сравнивать вещественные числа на равенство здесь нельзя. X = 2,918827 это бесконечная
дробь, попасть в неё узлом сетки практически невозможно, поэтому проверка `Y(X) == -10`
не сработала бы почти никогда. По той же причине совпадение стартовой точки с искомой
проверяется не равенством, а сравнением модуля отклонения с малой величиной ε.

Сама точка почти всегда лежит между узлами, так что после смены знака её положение
уточняется половинным делением последнего отрезка. Отрезок делится пополам, из двух
половин остаётся та, на концах которой отклонение всё ещё меняет знак, и так до ширины
10⁻¹⁰. За счёт этого ответ не зависит от того, насколько крупный шаг задал пользователь:
при h = 0,1 и при h = 0,5 получается одно и то же X = 2,918827.

Функция варианта убывает на всей числовой оси, поэтому уровень −10 она пересекает ровно
один раз. Если задать старт правее этой точки, отклонение знак уже не сменит, и проход
упрётся либо в предел числа шагов, либо в переполнение.

## Обработка исключений

Обработка разнесена по двум уровням, и это главное решение в работе.

Ошибки, которые пользователь может исправить прямо сейчас, обрабатываются там же, где
возникают. Ввод буквы вместо числа перехватывается внутри `InputModule`, программа пишет,
что именно не так, и повторяет запрос. Поднимать такое наверх смысла нет: работа не
испорчена, достаточно переспросить.

Ошибки, после которых продолжать бессмысленно, поднимаются до `Main`. Там четыре блока
`catch`:

| Исключение | Когда возникает |
| --- | --- |
| `InvalidStepException` | шаг задан нулём или отрицательным числом |
| `PointNotFoundException` | точка не встретилась за 10000 шагов |
| `ArithmeticException` | значение функции перестало быть конечным числом |
| `NoSuchElementException` | исходные данные закончились раньше времени |

Первые два это собственные проверяемые исключения, унаследованные от `Exception` через
общий `SearchException`. Они описывают ситуации предметной области, а не технические сбои,
поэтому и классы для них свои. Блок `finally` закрывает поток ввода независимо от того,
чем кончилась работа.

Отдельного внимания стоит проверка результата вычисления. Переполнение в Java не вызывает
исключения само по себе: `Math.exp(800)` просто возвращает бесконечность, и программа
спокойно продолжит считать с испорченным значением. Поэтому проверка стоит вручную, и
условие в ней составное:

```java
if (Double.isNaN(y) || Double.isInfinite(y)) {
    throw new ArithmeticException(...);
}
```

Одной проверки на бесконечность мало. При очень большом аргументе x² и eˣ обращаются в
бесконечность каждый по отдельности, а их разность даёт NaN, то есть «не число», которое
проверкой на бесконечность не ловится.

## Тестирование

Десять тест-кейсов. Каждый прогонялся по-настоящему, результаты в таблице это то, что
программа печатает, а не то, что ожидалось.

| № | Входные данные | Что проверяется | Результат |
| --- | --- | --- | --- |
| Т1 | X0 = 0, h = 0,1 | основной ход | точка на шаге 30, X = 2,918827 |
| Т2 | X0 = 0, h = 0,5 | крупный шаг | точка на шаге 6, X то же самое |
| Т3 | X0 = 0, h = 0 | нулевой шаг | `InvalidStepException` |
| Т4 | X0 = 0, h = −0,1 | отрицательный шаг | `InvalidStepException` |
| Т5 | X0 = 10, h = 0,1 | переполнение eˣ | `ArithmeticException` при x = 709,8 |
| Т6 | X0 = abc, затем 0; h = 0,1 | нечисловой ввод | сообщение и повторный запрос |
| Т7 | X0 = 10, h = 0,01 | предел числа шагов | `PointNotFoundException`, X = 110 |
| Т8 | введено только X0 | обрыв данных | `NoSuchElementException` |
| Т9 | X0 = 2,918826982306345, h = 0,1 | старт точно в точке | найдена на шаге 0 |
| Т10 | X0 = 1e200, h = 1 | разность двух бесконечностей | `ArithmeticException`, значение NaN |

Покрытие решений: у каждой развилки алгоритма закрыты обе ветви.

| Решение | Ветвь «да» | Ветвь «нет» |
| --- | --- | --- |
| h > 0 | Т1, Т2 | Т3, Т4 |
| модуль отклонения меньше ε | Т9 | Т1 |
| значение Y(X) конечно | Т1 | Т5, Т10 |
| Dпр · D ≤ 0 | Т1, шаг 30 | Т1, шаги с 1 по 29 |
| k < MAX_STEPS | Т1 | Т7 |
| строка преобразуется в число | Т1 | Т6 |
| есть очередная строка ввода | Т1 | Т8 |

Покрытие условий проверяется на составном условии про NaN и бесконечность: первая половина
истинна в Т10, вторая в Т5, обе ложны в Т1.

Покрытие операторов обеспечивает набор Т1, Т3, Т5, Т6, Т7, Т8 и Т9: вместе они выполняют
каждый оператор, включая все четыре блока `catch` и обе ветви печати протокола.

Пара вещей выяснилась только на прогоне. Т5 и Т7 задумывались как один тест: взять старт
правее точки и упереться в предел шагов. На деле при шаге 0,1 программа до предела не
доходит, раньше ломается экспонента, так что шаг пришлось уменьшить до 0,01. А тест Т10
появился после того, как стало ясно, что проверки на бесконечность недостаточно.

## Теоретическая часть

**Исключение** это объект, который создаётся при ошибке во время выполнения и прерывает
обычный ход программы. В Java они делятся на проверяемые, которые компилятор требует либо
перехватить, либо объявить в заголовке метода через `throws`, и непроверяемые, наследники
`RuntimeException`, про которые компилятор не напоминает. Перехват выполняется блоком
`try`, обработка блоком `catch`, а `finally` выполняется в любом случае и годится для
освобождения ресурсов.

**Собственное исключение** заводится наследованием от `Exception`. Это позволяет отделить
ошибки предметной области от технических и обработать их по-разному, не разбирая текст
сообщения.

**Отладка** это поиск и устранение ошибок в уже написанной программе. Основной её
инструмент это тесты, а качество набора тестов оценивают покрытием.

**Покрытие операторов** требует, чтобы каждый оператор выполнился хотя бы раз. Это самый
слабый критерий: программу с развилкой, у которой заполнена только ветвь «да», он считает
покрытой.

**Покрытие решений** строже: каждая развилка должна хотя бы раз пойти по «да» и хотя бы
раз по «нет».

**Покрытие условий** требует, чтобы каждое простое условие внутри составного приняло оба
значения. Для выражений с `||` и `&&` это важно: из-за сокращённого вычисления вторая
половина условия может ни разу не выполниться, хотя вся развилка формально покрыта.

**Вещественные вычисления** добавляют свои ошибки. Тип `double` не хранит числа точно,
поэтому проверять равенство двух вещественных значений оператором `==` нельзя, вместо
этого сравнивают модуль разности с малой величиной. Результат может выйти за пределы типа
и стать бесконечностью, а разность двух бесконечностей даёт NaN. Ни то, ни другое не
вызывает исключения, вычисления просто продолжаются с испорченным значением.

## Ответы на вопросы

Контрольных вопросов в методичке этого занятия нет, поэтому вопросы я составил по
теоретической части сам.

**1. Что такое исключение и чем оно отличается от обычной ошибки в коде?**

Исключение возникает во время выполнения, а не при компиляции, и прерывает нормальный ход
программы. В отличие от ошибки в логике, которая просто даёт неверный результат,
исключение нельзя не заметить: программа либо обработает его, либо завершится.

**2. Чем проверяемые исключения отличаются от непроверяемых?**

Проверяемые компилятор заставляет обработать: метод обязан либо перехватить их, либо
объявить в `throws`. Непроверяемые, наследники `RuntimeException`, такого требования не
несут. В этой работе собственные исключения сделаны проверяемыми, чтобы про них нельзя
было забыть.

**3. Для чего нужен блок finally?**

Он выполняется в любом случае: и когда исключения не было, и когда оно возникло, и когда
из блока `try` сделали `return`. Это место для освобождения ресурсов, здесь в нём
закрывается поток ввода.

**4. Зачем заводить собственный класс исключения?**

Чтобы отличать ситуации друг от друга по типу, а не по тексту сообщения. Неверный шаг и
ненайденная точка требуют разной реакции, и с двумя классами это два отдельных блока
`catch`, а не разбор строки внутри одного.

**5. Что такое покрытие операторов, условий и решений?**

Покрытие операторов требует выполнить каждый оператор хотя бы раз. Покрытие решений
требует пройти каждую развилку по обеим ветвям. Покрытие условий требует, чтобы каждое
простое условие внутри составного приняло оба значения. Каждый следующий критерий строже
предыдущего.

**6. Почему покрытия операторов недостаточно?**

Оно не замечает незаполненных ветвей. Если у развилки выполняется только «да», все
операторы программы могут оказаться пройденными, а ошибка в ветви «нет» останется
незамеченной. Так было бы и здесь: без тестов Т3 и Т4 проверка шага ни разу не сработала
бы.

**7. Почему вещественные числа нельзя сравнивать оператором ==?**

Тип `double` хранит числа приближённо, и результат вычислений почти никогда не совпадает
с ожидаемым значением бит в бит. Поэтому сравнивают модуль разности с малой величиной ε.
В этой программе так проверяется попадание в характерную точку.

**8. Почему переполнение при вычислении не вызывает исключения само по себе?**

Вещественная арифметика в Java устроена так, что вместо аварийного завершения возвращает
специальные значения: бесконечность при выходе за пределы типа и NaN для
неопределённостей вроде разности двух бесконечностей. Программа продолжает работать с
ними как с обычными числами, поэтому такую проверку приходится ставить вручную.
