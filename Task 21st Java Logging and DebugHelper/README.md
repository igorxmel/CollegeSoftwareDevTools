# ПЗ №21. Применение отладочных классов в проекте

Обработка заказов интернет-магазина на Java с журналированием через java.util.logging и вспомогательным классом DebugHelper. Методичка требует именно класс OrderService и заказы интернет-магазина, поэтому в заказах использованы товары магазина Dream Sneakers. Пример с оценками из методички нужен для сравнения и в проект не входит.

## Описание решения

```
Solution/
    src/
        OrderService.java
        DebugHelper.java
        Main.java
```

Проект состоит из трёх классов в пакете по умолчанию, поэтому открывается в IntelliJ IDEA как обычная папка с исходниками, а из командной строки собирается одной командой javac. Результат компиляции кладётся в build, эта папка в репозиторий не попадает.

Заказы взяты из каталога магазина Dream Sneakers: те же названия и цены, что в предыдущих работах. Стоимость пары хранится как double, количество как int. Тип int исключает дробные значения, поэтому проверка «целое число» из методички выполняется типом, а в методе остаётся проверка знака.

## Как запустить

Перейти в папку решения:

```
cd Solution
```

Скомпилировать классы:

```
javac -encoding UTF-8 -d build src/*.java
```

Запустить программу:

```
java -cp build Main
```

Нужен JDK. Проект проверялся на Java 25. Журнал выводится в стандартный поток ошибок, а информация о заказах в стандартный вывод, поэтому в консоли они идут вперемешку.

## Разбор классов

### OrderService

Метод calculateTotal сначала пишет в журнал начало обработки и полученные данные на уровне INFO. Потом проверяет цену и количество, и при ошибке пишет WARNING и выбрасывает IllegalArgumentException с понятным текстом. Предупреждение уходит в журнал до исключения, чтобы причина была видна даже тогда, когда вызывающий код исключение проглотит.

Для крупного заказа добавлена отдельная проверка. С количества 100 пар заказ считается крупным, и в журнал уходит WARNING о проверке остатков на складе. Это не ошибка, расчёт продолжается, но менеджеру стоит об этом знать. Порог вынесен в константу.

### DebugHelper

DebugHelper выводит данные заказа: название товара, стоимость одной пары, количество и итоговую сумму. Деньги форматируются в одном методе с двумя знаками после запятой и десятичной запятой по русским правилам. Отдельный метод printError показывает пользователю сообщение об ошибке в стандартный поток ошибок.

### Main

Main выполняет шесть заказов, которые перечисляются в методичке: корректный, с нулевой и отрицательной стоимостью, с нулевым и отрицательным количеством и крупный. Каждый проходит через processOrder. Метод перехватывает IllegalArgumentException и пишет её в журнал через logger.log(Level.SEVERE, ...) вместе со стеком, а пользователю печатает короткое сообщение. Вторым блоком catch ловится любая другая RuntimeException, чтобы непредвиденная ошибка тоже не обрушила программу. Отдельный Logger в Main объявлен по требованию методички: общий экземпляр у двух классов не нужен.

## Теоретическая часть

Журналирование это запись сообщений о ходе работы программы: что она начала делать, какие данные получила, что вычислила и где возникла ошибка. В отличие от System.out.println, журнал можно настраивать: у сообщений есть уровень важности, время и источник, а вывод можно направить в консоль, файл или внешнюю систему без правки кода, который пишет сообщения.

В Java для этого есть пакет java.util.logging. Класс Logger создаётся методом Logger.getLogger с именем, обычно это имя класса, и после этого получает сообщения от своего класса. Каждое сообщение сопровождается уровнем из класса Level, а по умолчанию записи выводятся в консоль со временем и названием метода.

Основные уровни три. INFO сообщает о ходе выполнения: начало и конец операции, полученные данные. WARNING предупреждает о проблеме, после которой работа ещё возможна или которую обработает вызывающий код, например о некорректных входных данных или крупном заказе. SEVERE отмечает серьёзную ошибку. Метод logger.log(Level.SEVERE, сообщение, исключение) записывает ещё и трассировку стека.

Вспомогательный класс отладки собирает в одном месте вывод, который нужен разработчику или пользователю: значения переменных, исходные данные, результат. Если форматирование вывода лежит в одном классе, бизнес-логика остаётся чистой, а формат ответа меняется в одном месте.

Входные данные проверяют до вычислений. Если стоимость отрицательна или количество равно нулю, расчёт либо даст бессмысленный результат, либо пропустит ошибку дальше по программе. Для некорректного аргумента в Java предусмотрено исключение IllegalArgumentException. Его выбрасывает метод, а перехватывает код, который знает, что делать пользователю: показать сообщение и записать ошибку в журнал.

## Ответы на вопросы

Вопросы взяты из методички.

**1. Для чего используются средства отладки и журналирования?**

Чтобы контролировать выполнение программы, проверять значения данных, находить причины ошибок и анализировать работу отдельных методов. Журнал остаётся после завершения программы, поэтому ошибку можно разобрать позже.

**2. Чем отличается System.out.println() от Logger?**

println просто печатает строку в консоль. Logger добавляет уровень важности, время и источник сообщения, позволяет отфильтровать записи по уровню и перенаправить их в файл, не меняя код, который пишет сообщения.

**3. Для чего предназначен класс Logger?**

Он принимает сообщения программы и передаёт их обработчикам, которые записывают их в консоль, файл или другое место. Для каждого класса обычно создаётся свой Logger с именем этого класса.

**4. Какие уровни журналирования используются в java.util.logging?**

От самого важного к менее важному: SEVERE, WARNING, INFO, CONFIG, FINE, FINER и FINEST. Есть также OFF и ALL для отключения и включения всех сообщений. В работе использованы INFO, WARNING и SEVERE.

**5. В каких случаях применяется уровень WARNING?**

Когда произошло нечто нежелательное, но программа может продолжить работу или ошибку обработает вызывающий код: некорректные входные данные, крупный заказ, пустой список. В работе так записаны неверная цена, неверное количество и заказ от 100 пар.

**6. Для чего используется уровень SEVERE?**

Для серьёзных ошибок, из-за которых операция не выполнена. В работе SEVERE пишется в Main при перехвате исключения вместе со стеком вызовов, чтобы по журналу можно было найти место сбоя.

**7. Какую задачу выполняет вспомогательный класс DebugHelper?**

Он собирает вывод диагностической информации в одном месте: значения переменных, данные заказа и итог вычислений. Бизнес-логика при этом не смешивается с форматированием вывода.

**8. Почему необходимо проверять входные данные перед выполнением вычислений?**

Некорректные данные дают бессмысленный результат или ошибку в другом месте программы, где причину найти сложнее. Проверка в начале метода останавливает обработку сразу и сообщает, что именно не так.

**9. Для чего используется исключение IllegalArgumentException?**

Оно сообщает, что методу передан недопустимый аргумент. В работе его выбрасывает calculateTotal при нулевой или отрицательной стоимости и количестве, а Main перехватывает и показывает сообщение.
