# Практическое занятие №12. AngularJS приложения

Пять заданий первого варианта на AngularJS: карточка студента на двусторонней привязке,
счётчик, список студентов с добавлением и удалением, переключение темы страницы и форма
регистрации с проверкой полей. Все пять собраны на одной странице, разделами.

## Описание решения

```
Solution/
    index.html    разметка всех пяти заданий и директивы AngularJS
    app.js        модуль practiceApp и пять контроллеров
    styles.css    оформление, в том числе тёмная тема
```

Методичка просит создать папку проекта и файл `index.html`, про остальные файлы ничего не
говорит, поэтому все пять заданий легли на одну страницу отдельными секциями: открывается
одним файлом, ничего переключать не надо. Скрипты и стили вынесены из `index.html`, иначе
пять заданий в одном файле превратились бы в кашу из разметки, CSS и JavaScript.

Модуль один, `practiceApp`, а контроллеров пять, по одному на задание. Так значения
разных заданий не пересекаются: поля карточки студента из первого задания и поля формы
регистрации из пятого называются почти одинаково, и в общей области видимости они бы
перетирали друг друга.

AngularJS подключён через CDN версии 1.8.2, как указано в методичке, поэтому для работы
страницы нужен интернет.

## Как запустить

Файл открывается в браузере напрямую, двойным щелчком по `index.html`, сервер не нужен.

Если нужно отдать страницу по HTTP, из папки `Solution` подойдёт встроенный сервер
Python:

```bash
python -m http.server 8936
```

Дальше http://localhost:8936.

## Разбор заданий

**Задание 1. Карточка студента.** Четыре поля связаны с одним объектом `student`, а
карточка читает его же свойства, поэтому обновляется прямо во время набора. Объект здесь
удобнее четырёх отдельных переменных: он задаётся в контроллере одной строкой и показывает,
что все четыре значения относятся к одной сущности.

**Задание 2. Счётчик.** Три функции в контроллере и три кнопки в разметке. Запрет
отрицательных значений сделан в двух местах:

```js
$scope.decrease = function () {
    if ($scope.count > 0) {
        $scope.count -= 1;
    }
};
```

и `ng-disabled="count === 0"` на кнопке уменьшения. Проверка в функции это настоящая
защита значения, а `ng-disabled` только подсказка пользователю: видно, что кнопка сейчас
ничего не сделает. Одного `ng-disabled` мало, он управляет лишь внешним видом элемента.

**Задание 3. Список студентов.** Массив объектов выводится через `ng-repeat`, количество
записей берётся как `students.length`, а не считается отдельной переменной, которую
пришлось бы обновлять при каждом изменении. Удаление идёт по индексу, который `ng-repeat`
даёт в `$index`:

```js
$scope.removeStudent = function (index) {
    $scope.students.splice(index, 1);
};
```

Пустые поля не добавляются, вместо записи выводится сообщение. После добавления поля
очищаются присваиванием нового объекта, а не сбросом свойств по одному. Это важно: в
массив кладётся новый объект, собранный из обрезанных значений, и если бы вместо этого
туда попал сам `newStudent`, то очистка полей стёрла бы уже добавленную запись, потому что
ссылка была бы одна и та же.

Сообщение «Список пока пуст» выводится через `ng-if` по условию `students.length === 0`.

**Задание 4. Переключение темы.** Контроллер темы висит на теге `body`, а не на секции,
потому что оформление меняется у всей страницы:

```html
<body ng-controller="ThemeController" ng-class="{ dark: isDark }">
```

`ng-class` в такой записи ставит класс `dark`, когда `isDark` истинно, и убирает его,
когда ложно. Сами цвета описаны в CSS правилами вида `body.dark`, скрипт их не трогает.
Остальные контроллеры оказываются вложенными в контроллер темы, и в AngularJS это
нормально: у каждого своя дочерняя область видимости.

Текст кнопки меняется выражением прямо в разметке, а текущее состояние подписано двумя
абзацами с `ng-if` и обратным условием, так что виден только один.

**Задание 5. Регистрация студента.** Форме задано имя `regForm`, и AngularJS сам кладёт в
область видимости объект с этим именем, по которому видно состояние формы и каждого поля.
Проверки навешены атрибутами: `required` на все четыре поля, `ng-minlength="2"` на фамилию
и имя, `ng-pattern` на почту. Регулярное выражение лежит в контроллере, потому что
`ng-pattern` получает выражение Angular, а не строку:

```js
$scope.emailPattern = /^[^\s@]+@[^\s@]+\.[a-zA-Z]{2,}$/;
```

Почту можно было бы проверить и через `type="email"`, у Angular для этого есть
встроенный валидатор, но в задании прямо названы средства `required`, `ng-minlength` и
`ng-pattern`, поэтому правило задано выражением: так видно, что именно считается верным
адресом.

На самой форме стоит `novalidate`, иначе до проверок Angular дело не дойдёт, браузер
покажет свои всплывающие подсказки и остановит отправку. Обработчик `ng-submit`
вызывается и при незаполненной форме, поэтому состояние проверяется внутри:

```js
if ($scope.regForm.$invalid) {
    $scope.registered = null;
    return;
}
```

Сообщения об ошибках показываются не сразу, а когда поле уже трогали или когда была
попытка отправки: условие `$touched || regForm.$submitted`. Иначе на только что открытой
странице все четыре поля сразу подсвечиваются ошибками, хотя пользователь ничего ещё не
вводил.

В карточку кладётся копия данных через `angular.copy`. Без копии карточка ссылалась бы на
тот же объект, что и поля формы, и менялась бы при дальнейшем вводе, хотя регистрация уже
принята.

## Проверка решения

Чтобы не перещёлкивать все пять заданий заново после каждой правки, я прогнал сценарии в
Node.js: разметка загружается в jsdom вместе с AngularJS, дальше скрипт меняет поля,
нажимает кнопки и сверяет результат. Что проверено:

| Задание | Что проверялось |
| --- | --- |
| 1 | карточка обновляется при изменении модели, ввод в поле меняет модель |
| 2 | увеличение, уменьшение, сброс, блокировка кнопки и отсутствие отрицательных значений |
| 3 | вывод массива, добавление, очистка полей, отказ при пустых полях, удаление, сообщение о пустом списке |
| 4 | класс `dark` на `body`, смена подписи и текста кнопки, возврат к светлой теме |
| 5 | пустая форма не отправляется, `ng-minlength` и `ng-pattern` ловят ошибки, при верных данных форма `$valid` и выводится карточка, карточка не меняется при правке полей |

Папка с этими проверками в репозиторий не попала: она тянет за собой jsdom и копию
AngularJS, а в задании такого не требуется.

## Теоретическая часть

**AngularJS** это фреймворк JavaScript от Google для динамических веб-приложений. Он
связывает данные с разметкой, обрабатывает действия пользователя и обновляет интерфейс без
перезагрузки страницы. Версия 1.x, с которой работает эта работа, считается устаревшей и
отличается от современного Angular, который переписан заново и построен на компонентах и
TypeScript.

**Директивы** это особые атрибуты HTML, задающие элементам поведение.

| Директива | Назначение |
| --- | --- |
| `ng-app` | обозначает область приложения |
| `ng-model` | связывает поле ввода с данными |
| `ng-bind` | выводит значение выражения |
| `ng-init` | задаёт начальные данные |
| `ng-repeat` | повторяет элемент по массиву |
| `ng-click` | обрабатывает нажатие |
| `ng-if` | создаёт элемент при выполнении условия |
| `ng-show`, `ng-hide` | показывают и скрывают элемент |
| `ng-submit` | обрабатывает отправку формы |
| `ng-class` | добавляет класс по условию |
| `ng-disabled` | блокирует элемент управления |

**Двусторонняя привязка** означает, что данные и интерфейс синхронизированы в обе стороны:
ввод в поле меняет переменную, а изменение переменной из кода обновляет всё, что её
выводит. Выражения в разметке записываются в двойных фигурных скобках.

**Контроллер** определяет данные и функции приложения. Связь с разметкой идёт через объект
`$scope`: всё, что в него положено, доступно в том участке страницы, где объявлен
контроллер. Контроллеры объявляются внутри модуля, а модуль это именованный контейнер для
частей приложения, который указывается в `ng-app`.

**Проверка форм.** Форме дают имя, и AngularJS создаёт в области видимости объект с
состоянием формы и её полей. Правила задаются атрибутами `required`, `ng-minlength`,
`ng-maxlength`, `ng-pattern`. Состояние читается по свойствам `$valid`, `$invalid`,
`$touched`, `$dirty`, `$submitted`, а причина ошибки по объекту `$error`. Браузерную
проверку при этом отключают атрибутом `novalidate`.

## Ответы на контрольные вопросы

**1. Что такое AngularJS и для чего он используется?**

Фреймворк JavaScript для веб-приложений, работающих в браузере без перезагрузки страницы.
Он берёт на себя связывание данных с разметкой, обработку событий, вывод списков, проверку
форм и разбиение приложения на модули и контроллеры.

**2. Для чего предназначены ng-app и ng-model?**

`ng-app` помечает элемент, внутри которого работает приложение, и указывает его модуль.
Всё, что вне этого элемента, фреймворк не обрабатывает. `ng-model` связывает поле ввода с
переменной области видимости, создавая двустороннюю привязку.

**3. Что такое двусторонняя привязка данных?**

Это синхронизация модели и интерфейса в обе стороны. Пользователь вводит значение, и
переменная меняется сама, без обработчика события. Код меняет переменную, и обновляется
всё, что её выводит. В первом задании поэтому карточка студента заполняется прямо во время
набора.

**4. Какую роль выполняет $scope?**

Это объект, через который контроллер и разметка видят одни и те же данные. Свойства
`$scope` доступны в выражениях того участка страницы, где объявлен контроллер, а функции
из него вызываются директивами вроде `ng-click`. У каждого контроллера своя область
видимости, и вложенные области наследуются от внешних, как в моём случае секции наследуют
от области контроллера темы.

**5. Для чего используются ng-click и ng-repeat?**

`ng-click` задаёт выражение или функцию, которая выполнится при нажатии на элемент.
`ng-repeat` повторяет элемент для каждой записи массива и даёт внутри переменную записи и
её номер в `$index`. В третьем задании список студентов строится `ng-repeat`, а кнопки
добавления и удаления работают через `ng-click`.

**6. Чем отличаются ng-if, ng-show и ng-hide?**

`ng-show` и `ng-hide` управляют видимостью: элемент остаётся в документе, ему просто
добавляется класс, скрывающий его стилями. `ng-if` действительно удаляет элемент из
документа, когда условие ложно, и создаёт заново, когда оно становится истинным, причём с
новой дочерней областью видимости. Когда скрытого содержимого много, `ng-if` экономнее:
Angular не следит за выражениями внутри удалённого участка.

**7. Как проверяются данные формы?**

Форме дают имя через атрибут `name`, и AngularJS кладёт в область видимости объект с этим
именем. Правила задаются атрибутами полей: `required`, `ng-minlength`, `ng-pattern` и
другими. Дальше читаются свойства `$valid` и `$invalid` у формы и у каждого поля, а
причина ошибки видна в `$error`, по ней и показывается нужное сообщение. Браузерную
проверку отключают атрибутом `novalidate`, иначе она сработает первой.

**8. Почему проверка данных необходима также на сервере?**

Потому что проверка в браузере защищает только от случайных ошибок пользователя, а не от
намеренных. Скрипты на странице можно отключить или изменить в инструментах разработчика,
а запрос к серверу отправить и вовсе без страницы, напрямую. Сервер получает данные
неизвестного происхождения, поэтому обязан проверить их сам, иначе в базе окажутся
значения, которые он никогда не принял бы от формы.
