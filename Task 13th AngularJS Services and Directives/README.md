# Практическое занятие №13. Написание собственных сервисов AJAX и директив

Приложение на AngularJS, которое получает список пользователей с публичного API
jsonplaceholder и выводит их карточками. Работа разделена на три части: сервис знает, как
получить данные, контроллер когда их запросить и что положить в область видимости,
директива как показать одну карточку. В методичке дан каркас всех трёх частей, в котором
не хватало шаблона директивы и обработчиков успеха и ошибки.

## Описание решения

```
Solution/
    index.html    разметка: контроллер, индикатор загрузки и сетка карточек
    app.js        модуль UserApp: сервис, директива и контроллер
    styles.css    оформление сетки и карточки
```

Разметка в `index.html` собрана по методичке: `ng-app="UserApp"` на теге `body`,
контейнер с `ng-controller="UserListController"`, внутри блок с `ng-if="isLoading"` и блок
с классом `user-grid`, а в нём `ng-repeat` вместе с пользовательской директивой:

```html
<user-card ng-repeat="user in users" user-data="user"></user-card>
```

Сверх этого на странице два блока, которых в задании прямо нет: сообщение об ошибке с
кнопкой повтора и строка с количеством полученных записей. Сообщение понадобилось потому,
что блок `catch` требовалось написать самому, а без вывода на страницу об ошибке узнал бы
только тот, кто смотрит в консоль.

AngularJS подключён через CDN версии 1.8.2, как и в прошлой работе, поэтому странице нужен
интернет. Данные тоже приходят из сети, запросов к ним ровно один при открытии страницы.

## Как запустить

Файл открывается в браузере напрямую, двойным щелчком по `index.html`, сервер не нужен.

Если нужно отдать страницу по HTTP, из папки `Solution` подойдёт встроенный сервер
Python:

```bash
python -m http.server 8936
```

Дальше http://localhost:8936.

## Разбор решения

**Сервис.** Адрес API и сам запрос лежат в `UserService`, больше нигде в приложении про
сеть не знают. Метод возвращает промис, который ему вернул `$http.get`, и не разбирает
ответ:

```js
this.getUsers = function () {
    return $http.get(apiUrl);
};
```

Разбирать ответ здесь было бы лишним шагом: контроллеру всё равно нужен промис, чтобы
показать индикатор загрузки на время запроса и отреагировать на ошибку. Сервис объявлен
через `.service()`, то есть функцией-конструктором: AngularJS создаёт объект через `new`
один раз на всё приложение, а публичными становятся методы, записанные в `this`.

**Директива.** Шаблон карточки я написал сам. Внутри используется имя `user`, то самое,
которое объявлено в изолированной области видимости:

```js
scope: {
    user: '=userData'
}
```

Запись `=userData` связывает внутреннее свойство `user` с атрибутом `user-data` из
разметки, а `ng-repeat` на каждом шаге подставляет в этот атрибут очередную запись
массива. Изолированная область видимости здесь означает, что директива не видит
переменные контроллера и работает только с тем, что ей передали. Если бы области видимости
не было, все десять карточек читали бы `user` из цикла и при этом могли бы случайно
перетереть переменные контроллера.

Имя директивы в коде записано как `userCard`, а в разметке тег называется `user-card`: имя
в стиле camelCase фреймворк сам переводит в написание через дефис.

В шаблоне выводятся и вложенные поля ответа, `user.address.city` и `user.company.name`.
Поля в этом API не плоские, адрес и компания приходят отдельными объектами.

Оформление карточки навешено не на сам тег `user-card`, а на вложенный `div` внутри
шаблона. Браузер про такой тег ничего не знает и считает его строчным, поэтому ни рамка,
ни отступы на нём толком не работают.

**Контроллер.** Он инжектирует сервис, держит два состояния из задания, `users` и
`isLoading`, и обрабатывает промис тремя блоками. В `then` данные берутся из `response.data`:

```js
$scope.users = response.data;
```

Сам `response` это не массив, а объект ответа, в котором кроме данных лежат статус и
заголовки, поэтому без `.data` в карточки попало бы совсем не то.

В `catch` я очищаю список и записываю сообщение с кодом ответа. Очистка нужна для повтора
запроса: если первый запрос прошёл, а второй упал, старые карточки остались бы на экране
вместе с сообщением об ошибке. По той же причине в начале `loadUsers` сбрасывается
прошлая ошибка, иначе сообщение осталось бы висеть после удачной попытки.

Флаг загрузки снимается в `finally`, то есть один раз для обоих исходов. Это ровно тот
случай, для которого этот блок и нужен: иначе `isLoading = false` пришлось бы писать
дважды, и при ошибке индикатор легко забыть убрать.

**Разделение ответственности.** Если смотреть на решение целиком, то ни контроллер, ни
директива не знают адреса API, а сервис и директива ничего не знают про состояние
страницы. Проверяется это просто: смена адреса API затрагивает только сервис, правка
внешнего вида карточки только шаблон директивы и стили, а добавление кнопки повтора
только контроллер и разметку.

## Проверка решения

Как и в прошлой работе, сценарии я прогнал в Node.js: страница отдаётся локальным
сервером, загружается в jsdom вместе с AngularJS и делает настоящий запрос к API.
Что проверено:

| Что проверялось | Результат |
| --- | --- |
| директива отрисовала десять карточек | 10 тегов `user-card`, в каждом шаблон |
| данные в первой карточке | Leanne Graham, Sincere@april.biz |
| вложенные поля | город Gwenborough, компания Romaguera-Crona |
| последняя карточка | Clementina DuBuque |
| контроллер положил данные в область видимости | массив из десяти записей |
| индикатор загрузки | убран после ответа |
| изолированная область видимости директивы | своё свойство `user`, равное записи из массива |
| сбой запроса | показано сообщение с кодом ответа, карточек нет, индикатор убран |

Ошибочный сценарий проверялся подменой адреса в копии файла на несуществующий путь: ответ
с кодом 404 уходит в `catch` так же, как ушёл бы сетевой сбой.

Папка с этими проверками в репозиторий не попала: она тянет за собой jsdom и копию
AngularJS, а в задании такого не требуется.

## Теоретическая часть

**Разделение ответственности** это принцип, на котором построена вся работа. Сервис
отвечает за данные и сетевой код, контроллер за состояние и бизнес-логику, директива за
представление и работу с документом. Выигрыш в том, что каждую часть можно менять и
переиспользовать отдельно: тот же сервис подключается в другой контроллер, та же директива
выводит карточку из любого массива.

**Сервисы** это синглтоны, то есть объекты, созданные в единственном экземпляре на всё
приложение. Метод `.service()` принимает функцию-конструктор: фреймворк создаёт объект
через `new`, и публичными становятся методы, записанные в `this`. Похожий метод
`.factory()` отличается тем, что сам возвращает объект.

**Сервис $http** это встроенное средство AngularJS для запросов AJAX. Его методы `get`,
`post`, `put` и другие возвращают промис, у которого есть три обработчика: `then` при
успешном ответе со статусом из диапазона 200-299, `catch` при ошибке и `finally`,
выполняемый всегда. Объект `response` в `then` содержит `data` с данными от сервера,
`status` с кодом ответа, а также заголовки и исходную конфигурацию запроса.

**Директивы** позволяют собрать свой элемент интерфейса. Имя регистрируется в стиле
camelCase, а в разметке пишется через дефис. Настройка `restrict: 'E'` разрешает
использовать директиву только как тег, `template` задаёт разметку, которая подставится
вместо него, а блок `scope` создаёт изолированную область видимости. Привязка со знаком
равенства двусторонняя: значение берётся из атрибута в разметке и связывается с внутренним
свойством.

**Директива ng-repeat** проходит по массиву, на каждом шаге создаёт локальную переменную с
текущей записью и повторяет элемент вместе со всем, что на нём написано. В этой работе
повторяется тег директивы, и запись передаётся внутрь через атрибут.

## Ответы на вопросы

Контрольных вопросов в методичке этого занятия нет, поэтому вопросы я составил по
теоретической части сам.

**1. Зачем выносить запрос к API в сервис, если его можно выполнить прямо в контроллере?**

Чтобы сетевой код лежал в одном месте и переиспользовался. Адрес API знает только сервис,
поэтому при его смене правка одна, а не по всем контроллерам. Заодно контроллер остаётся
про состояние страницы, его проще читать.

**2. Чем .service() отличается от .factory()?**

`.service()` принимает функцию-конструктор, фреймворк вызывает её через `new`, и методы
записываются в `this`. `.factory()` принимает обычную функцию, которая сама возвращает
объект. Результат в обоих случаях один и тот же объект-синглтон на всё приложение.

**3. Что возвращает $http.get и какие обработчики есть у этого результата?**

Промис. У него `then` для успешного ответа, `catch` для ошибки и `finally`, который
выполняется в любом случае.

**4. Что лежит в объекте response и почему данные берутся из response.data?**

Кроме самих данных там статус ответа, заголовки и конфигурация запроса. Массив
пользователей это только часть ответа, поэтому берётся `response.data`, иначе в область
видимости попал бы весь объект ответа.

**5. Для чего нужен блок finally, если флаг загрузки можно снять в then и catch?**

Чтобы не писать одно и то же дважды и не забыть про ветку ошибки. Снятие индикатора
нужно при любом исходе, а это ровно то, что делает `finally`.

**6. Как имя директивы в коде связано с именем тега в разметке?**

Имя регистрируется в стиле camelCase, а в разметке пишется через дефис, поэтому
`userCard` в коде превращается в `<user-card>` на странице.

**7. Что делает настройка restrict: 'E'?**

Ограничивает способ использования директивы: только как отдельный тег. Другие значения
разрешают применять её как атрибут, класс или комментарий.

**8. Что такое изолированная область видимости директивы?**

Это своя область видимости, не наследующая переменные родителя. Директива видит только то,
что ей передали через атрибуты, поэтому её переменные не конфликтуют с переменными
контроллера и других директив.

**9. Как данные из ng-repeat попадают внутрь директивы?**

Через атрибут. На каждом шаге цикла локальная переменная подставляется в `user-data`, а
объявление `user: '=userData'` связывает этот атрибут с внутренним свойством `user`, по
которому работает шаблон.

**10. Почему оформление карточки задано вложенному div, а не самому тегу user-card?**

Потому что тег неизвестен браузеру и по умолчанию считается строчным, а рамка, отступы и
растягивание по ячейке сетки на строчном элементе работают не так, как нужно.
